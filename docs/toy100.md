# 100-mode convergence gate

The 100-mode suite trains the public `GANTrainer` on three unlabelled 2D
distributions: a square Gaussian grid, a rotated grid, and a staggered grid.
Each has 100 equally weighted modes with standard deviation 0.03. The trainer
receives real samples; target centers are used only to sample data, score
generated samples, and draw the diagnostic animation.

## One shared recipe across all 22 toys

The combined gate requires one optimizer, loss, learning-rate schedule, and
noise policy across the three 100-mode problems and all 19 canonical transfer
toys. Each older host retains its frozen data, architecture declaration,
resource sizes, budget, and thresholds. Per-family optimizer or noise overrides
cannot supply a combined PASS. The public-default replay is a separate control.

```bash
# Match the trained CI gate's x86 CPU dispatch profile.
export ATEN_CPU_CAPABILITY=avx2 MKL_ENABLE_INSTRUCTIONS=AVX2
export ONEDNN_MAX_CPU_ISA=AVX2 DNNL_MAX_CPU_ISA=AVX2
python -u -m benchmarks.toy_suite run --config configs/toy100/shared_candidate.json \
  --output artifacts/toy-suite/candidate --with-default-control
python -m benchmarks.toy_suite regrade --output artifacts/toy-suite/candidate
python experiments/leaderboard.py --toy-suite-output artifacts/toy-suite/candidate
tail -F artifacts/toy-suite/candidate/toy100.log
tail -F artifacts/toy-suite/candidate/candidate19.log
```

The combined report lists every case and exits nonzero for failures or missing
evidence. CI pins PyTorch, oneDNN, and MKL dispatch to AVX2 and records the
runtime profile. Two earlier CI runs with identical source and configuration
produced different image-toy trajectories on AVX2 and AVX512 runners; the
[CI audit](../reports/toy100/ci-common22.md) retains those failures. This profile
is a reproducibility control, not a claim of bitwise agreement across machines.
The historical `recommended.json` passes the original three-problem
coverage gate; it is **not a passing common-22 or stricter-accuracy recipe**.
The [accuracy audit](../reports/toy100/accuracy-diagnostics.md) and
[new search ledger](../reports/toy100/accuracy-search-ledger.md) retain this
distinction and the unsuccessful candidates.

`shared_candidate.json` is the current **failing** common recipe under search,
with identical settings on all 22 hosts. Pull-request CI trains and applies
the full common gate to this file, retaining all evidence on failure. A green
original three-problem coverage run does not satisfy that CI contract.
The current candidate passes **20/22** in the full trained CI run and
independent artifact regrades: grid100, staggered100, and 18/19 older toys.
Rotated100 covers all modes and passes its holdout, but precision at step
6000 is .96935, below .97, leaving four of five terminal checks passing.
`residual_student` also fails. The [CI audit](../reports/toy100/ci-common22.md)
retains the complete failing result.

The latest [experimental configuration](../reports/toy100/accuracy-network-horizon/README.md)
passes strict accuracy on all three 100-mode problems under identical settings.
It uses a trainable affine generator, a generic uniform-square particle
initialization, and a 1,600-update learning-rate horizon for G and D while the
prior follows its full-budget schedule. The [GIF](../reports/toy100/accuracy-network-horizon/toy100-progress.gif)
shows the saved live samples and accuracy metrics. All five final checks and
independent 100k holdouts pass, but the matching optimizer/noise core still
fails four of the older 19 toys. This is not a passing common-22 recipe.

```bash
python -m benchmarks.toy100 accuracy --output reports/toy100/accuracy-network-horizon
# Expected: PASS, 3/3 experimental cases.
```

To investigate an individual problem under the stricter gate:

```bash
python -u -m benchmarks.toy100 run --config path/to/candidate.json \
  --problem grid100 --require-accuracy --output artifacts/toy-suite/grid
python -m benchmarks.toy100 accuracy --problem grid100 \
  --output artifacts/toy-suite/grid
```

The accuracy gate adds four fixed limits: mode-mass TV ≤0.06, mode-center RMS
error ≤0.20 target standard deviations, absolute mean covariance trace bias
≤0.10, and radial KS distance ≤0.04. Conditional moments use the analytic
3σ-truncated Gaussian reference. Original coverage criteria remain mandatory.
All five terminal 20,000-draw checkpoints and a separate 100,000-draw holdout
must pass on live weights. Saved samples are independently rescored; EMA is
diagnostic. Qualifying training runs retain this evidence automatically.

## Declared affine model and shared network schedule

[`accuracy_shared_policy.json`](../configs/toy100/accuracy_shared_policy.json)
puts the experimental architecture and schedule into the normal runner. It is
a candidate under verification, not a passing 22-case recommendation:

```bash
python -u -m benchmarks.toy_suite run \
  --config configs/toy100/accuracy_shared_policy.json \
  --output artifacts/toy-suite/affine-policy --with-default-control
```

`toy100_model: "affine_square_v1"` declares a trainable identity-initialized
2D affine generator and learned particles initialized uniformly on [-5, 5]².
This initialization uses no target centers or samples. The same model card
applies to all three new problems; older hosts retain their frozen models.

`network_lr_horizon_cap: 1600` applies one schedule rule to every host:
G and D use the existing cosine with horizon `min(total_steps, 1600)`, while
the learned prior uses the full-budget cosine. All roles continue training.
For the older hosts, whose budgets are at or below 1,600, this cap is an exact
no-op. Actual optimizer-group rates are recorded at every update and checked
against the declaration. Model/schedule fields cannot vary in
`problem_overrides`, and scratch trainer substitutions cannot qualify for
the combined gate.

In the archived experiment, every new problem first covers all 100 modes at
update 750, but strict accuracy first passes at 6,000. Early coverage and
sustained Gaussian accuracy are therefore reported separately.

The optional `network_lr_floor` sets the cosine floor for G and D only;
the prior keeps `lr_floor`. It requires `network_lr_horizon_cap` and applies
on every host, including older hosts with budgets below the cap. Omitting
the field preserves the original floor. The gate checks the same declared
floor across all 22 cases and verifies actual rates at every update.
[`accuracy_network_floor.json`](../configs/toy100/accuracy_network_floor.json)
is a retained experiment, not a passing recommendation. Its
[native accuracy result](../reports/toy100/network-floor-native.md) and
[transfer screen](../reports/toy100/network-floor-screen.md) are recorded
separately.

New policy runs archive every Python module in `particlegan`, together with
the native runner and policy code. The combined gate verifies the archive
contents and requires matching public-source file sets and hashes across
native and transfer runs. Historical policy archives with limited source
coverage remain regradable as numerical evidence, but cannot establish a
new common-22 PASS.

## Run every problem or inspect one

Install the experiment and test extras from the repository root:

```bash
python -m pip install -e '.[experiments,dev]'
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python -u -m benchmarks.toy100 run \
  --output artifacts/toy100/gate
```

The default is [`recommended.json`](../configs/toy100/recommended.json):
7,000 updates per problem on one CPU thread. The command trains all three,
scores their live weights together, writes a leaderboard and convergence GIF,
and exits nonzero if any problem fails. Use a fresh output directory each time.
The recorded CPU suite takes about six minutes plus rendering; hardware and
library versions affect both timings and numerical trajectories.

```bash
python -u -m benchmarks.toy100 run \
  --problem grid100 --output artifacts/toy100/grid
python -m benchmarks.toy100 gate --output artifacts/toy100/gate
python experiments/leaderboard.py --toy100-output artifacts/toy100/gate
python -m benchmarks.toy100 render --output artifacts/toy100/gate
tail -f artifacts/toy100/grid/grid100/progress.log
python -m pytest -q tests/test_toy100*.py
```

Choose `grid100`, `rotated100`, or `staggered100` for an individual run.
`--no-render` skips GIF generation. `--steps` changes the total budget and its
relative annealing schedules, so it creates a new trajectory, not a truncated
replay. `--device cuda:0` enables GPU experiments; the final all-problem
recommendation was selected and verified on CPU.

## Historical coverage configuration and retained failures

The following configuration predates the stricter accuracy protocol and the
one-recipe requirement. Its per-problem batch override cannot qualify as the
final shared recipe. The public default misses modes and within-mode spread in the initial
reproduction. Ordinary learning-rate, annealing, batch, and architecture
searches did not satisfy the complete gate. The selected toy configuration
adds fresh Gaussian generator output noise (σ=0.026) and discriminator input
noise (σ=0.5, linearly reduced to zero by update 3,500). Output noise contributes
to the generated distribution during both training and evaluation; it is not
an evaluator correction. Neither mechanism uses target centers or labels.

The base batch size is 512. `problem_overrides` explicitly raises staggered's
batch to 1,024 after the shared 512 configuration left one mode underweight.
All other settings, the seed, and the scoring protocol are shared. A saved
`run_manifest.json` binds each run to its declared configuration and command
overrides. These are explicit benchmark settings; `get_recipe("gan")` keeps
its existing public defaults.

[Before/after results and GIFs](../reports/toy100/README.md) and the
[complete search ledger](../reports/toy100/search/README.md) preserve successes
and failures. This is fixed-seed regression evidence, not a multi-seed
robustness claim. The unchanged baseline remains runnable and fails the gate:

```bash
python -u -m benchmarks.toy100 run \
  --config configs/toy100/baseline.json --output artifacts/toy100/baseline
# Expected exit status: 1.
```

The trained GitHub Actions gate runs all 22 problems under the shared candidate
on CPU for relevant pull requests and uploads logs, metrics, and samples even
on failure. Unit tests separately exercise oracle samples, collapsed modes,
missing evidence, and the training/evaluation RNG separation.

## What counts as success

Every evaluation draws 20,000 generated samples. A covered mode must hold at
least 0.5% of all draws within three standard deviations of its center. The
joint quality check requires all 100 modes, at least 97% in-radius samples,
mode-mass total variation at most 0.10, and no mode holding more than 2% of
the samples. Per-mode covariance and radial-width checks reject collapsed
centers and lines that can fool a coverage-only score. These are numerical
acceptance criteria, not a proof that each learned component is Gaussian.

The covariance eigenvalues of each in-radius population, divided by the
target variance, must all lie in [0.40, 1.70]. Each mode's median radius,
relative to the truncated Gaussian reference, must lie in [0.65, 1.40]. Every
sample must be finite. The thresholds are fixed in `benchmarks/toy100/metrics.py`.

The gate scores live weights. EMA is a separate diagnostic. The first frame
is the untouched model at step zero, followed by dense early evaluations and
regular checkpoints. A pass requires five consecutive terminal evaluations
within the declared update budget; a favorable intermediate checkpoint does
not rescue a later collapse. Missing, malformed, or incomplete evidence fails
the gate. Training and evaluation use separate random-number streams.
The exact final 20,000 generated draws are retained for independent rescoring;
all checkpoints retain visualization samples and complete numerical metrics.

The leaderboard reports first full coverage and stable quality convergence,
alongside final quality and training time. GIFs show saved generated samples
at their actual training steps on fixed axes. Numerical traces determine the
verdict; the GIF is a diagnostic aid.

## Compare configurations

Keep the seed and scoring protocol fixed, change configuration fields, and
retain failures as well as successes. This suite is a configuration and task
comparison, not a seed sweep. Do not compare timings across devices or count
an EMA-only success as a live-weight pass. The historical regularizer board
and the 19-task transfer board retain their original protocols; this stricter
100-mode board adds a separate regression gate.

The search runner retains each attempted configuration and its verdict:

```bash
python -u -m benchmarks.toy100.search \
  --base configs/toy100/baseline.json --candidates path/to/candidates.json \
  --problem grid100 --device cuda:0 --output artifacts/toy100/search
```

The candidate file is a JSON array of objects with `name` and `overrides`.
For example, `[{"name":"lower_lr","overrides":{"lr":0.0006}}]` changes
only the learning rate. Omit `--problem` to train all three problems for each
candidate. A search's ranking never changes the acceptance criteria.

## Shared learnable-noise experiment

`configs/toy100/accuracy_learnable.json` is an experimental shared rule, not a
passing recommendation. It adds one trainable scalar to each host's output
wrapper. All runs initialize the scale identically and optimize its softplus
parameter with the generator's ordinary Adam group; the declared warmup
multiplies that learned scale. Discriminator updates do not train the scalar.
Native EMA models and custom hosts that maintain generator EMA also average
this parameter. The base host architectures, data, budgets, and thresholds
stay unchanged; the extra scalar is separately counted in the receipts.

The combined gate requires the same `output_noise_learnable` flag across all
22 runs and checks the scalar's generator ownership, scheduled amplitude,
actual noise trace, and final live/EMA values. Toy100 train-event noise values
are recorded **after** each update, at its evaluation amplitude; that update
used the preceding completed-step warmup value. The flag defaults to false
and is absent from historical fixed-noise manifests.

## Optional isolated output-noise stream

Set `output_noise_rng: "isolated"` once in a shared candidate manifest to draw
generator output noise from a private stream seeded at the declared training
seed plus 1,901. The field requires positive `output_noise_std` and cannot
appear in a per-problem override. Discriminator input noise keeps its own
existing stream. Each generator wrapper saves its stream and draw counters in
checkpoints, so resumed training replays the same noise. Scored evaluations
and the independent holdout use fixed private draws, then restore the training
stream. Omitting the field preserves the historical wrapper and RNG behavior.

The [combined gate](../benchmarks/toy_suite.py) requires the same selector on
all 22 hosts. It checks saved stream seeds, training draws, evaluation-state
restoration, and every generated-sample checkpoint; native selected runs also
require the full portable V2 source archive. The selector works with or without
the affine model and network-horizon options. See the experimental
[affine shared candidate](../configs/toy100/shared_candidate_isolated_rng.json)
and [native accuracy candidate](../configs/toy100/accuracy_shared_policy_isolated_rng.json).
Neither candidate is a demonstrated 22-task pass; saved transfer replays are
documented in the [isolated RNG validation](../reports/toy100/isolated-rng-validation.md).
