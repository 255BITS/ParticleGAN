# Lunar consolidation against `develop`

The audit started at `fde698b`; the combined branch was rebased onto `3d08a3a`
and the complete command and test suite were rerun against that API.

The single Lunar pipeline should start from the current `develop` API and own collection, training, evaluation, and evidence under one command. The old PRs have different bases (`feature/gym-world-model` or `particle-finetune/base`); their GitHub diff sizes are therefore not the amount of work missing from `develop`. This map records the useful behavior, not an instruction to merge their branches.

The baseline to protect is the cited YuE2 paired-error result: 20/20 validation, 50/50 test, mean test return 287.7. Those numbers come from an earlier run and are not a measurement of this branch. The current implementation's `lib/gym_particle_finetune.py` exposes `controller_objective` and `discriminator_objective`; keep action MSE diagnostic only and retain the `adv_weight=1` check. Lunar continuous action has **main engine on when action[0] > 0** and side thrust on when `abs(action[1]) > 0.5`; a faster landing needs actual earlier, controlled descent, not a shorter crash or timeout.

The full run should report a small, tail-friendly leaderboard for safe teacher, held fast teacher, and trained student on the **same frozen validation resets**. Show successful landings, crashes, timeouts, mean return, and mean steps **among successful landings only**; also show paired per-seed step differences where both land. Choose checkpoints on validation landing rate first, then successful-landing steps or return with the rule declared before testing. A teacher held after only one successful probe (`#25` default `min_held_landings=1`) is insufficient evidence of safe speed; require a meaningful landing floor against the safe reference before promotion. Keep collection/training resets separate from validation/test, and run the frozen test set only on the selected candidate. An honest speed claim requires comparable success on held-out worlds and fewer success steps; report any success loss explicitly.

Render slow and fast GIFs from real, same-seed simulator rollouts with a shared FPS and frame policy. Label seed, controller checkpoint, outcome, steps, and return alongside each artifact so a quick crash cannot be mistaken for speed. A fast GIF is evidence of behavior, while the paired rollout table is the quantitative result. If the full run has not completed, mark its Lunar leaderboard and GIFs pending rather than borrowing toy or prior PR numbers.
