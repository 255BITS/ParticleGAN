# REQUIREMENTS: a portable, LR-free particle-GAN formulation (draft 7, 2026-09-29)

Purpose: let agents experiment and find the best algorithm without re-deriving the rules each time. A *solution* must (a) pass the acceptance tests (section 4), (b) obey the admissibility rules (section 2, which serve the one rule of section 0.0),
(c) ship the evidence (section 5). The point is a GAN that ports to other datasets and data types without anyone re-adapting it; a fix that only works for the benchmark, or that needs data-specific inputs, is informative but is not a solution.

History: draft 1 was stress-tested by two independent classifiers (13 mechanisms, agreement 6/13), a red-team (11 loopholes, 8 over-strict readings) and a spec-only tester (13 gaps; it then designed the far-field
candidate F1 from the text alone). Draft 2 fixed those; round 2 (17 mechanisms) reached 15/17 agreement on the RULES label, 14/17 on status, and a path/consistency audit found 8 of 16 cited artefacts broken or
stale. Draft 3 fixes them (the ledger/label/flag semantics, S1b release definition, test definitions, the fixture and lint that were missing). Draft 4 (evening) adds the first I2-free 3/3 (candidate E4, `gan-attempts/noout-20260928/`, RESULTS.md and README.md there), the measured stray/jitter/release anatomy (section 6), its attribution, S4 result, dead ends and directions. Draft 5 (2026-09-29) is rewritten around the user's plain rule (section 0.0): the model's own components may be changed freely, data space may not be used. That retires the I2 sink rule and the frozen-critic rule, makes an averaged model of record and feature-space comparisons admissible,
promotes portability (S3) to the headline acceptance test, and records the first rule-compliant 3/3 (candidate E9/E10, `gan-attempts/noout-20260928/`). Draft 6 (2026-09-29, after two independent reviews of E11) corrects it: the base's drift statistic is live on the shift task (removed, E12), "the critic's feature space" is defined (all learned scalar heads; a raw skip head is excluded, E14), the stale-reset bug and the miscalibrated gate null are repaired (E13), and the current candidate is E14s (RESULTS 0). Read section 7 (what is known) and section 8 (dead ends) first.

## 0.0 The rule and the priority (the user's words, 2026-09-28)
"You can use and modify the z, the particles, the generator, the discriminator, the trainer: anything from the network that is not specific to the problem." "Data space is not allowed." "Averaged model: allowed." "Fakes vs reals in feature space: allowed."
"Beating 100g is worth more than beating the other toys, because it is rare." The goal behind it: one config that is easily adaptable to different datasets and different data types, so nothing may need re-adapting when the dataset or data type changes.
- **May be read and changed:** the latent z, the particle table rows, the generator, the discriminator (architecture, loss, penalties, optimizer, init), the trainer and its controllers, the optimizers, and the served model (an averaged model of record is allowed).
- **May be computed:** any statistic of those internals (gradients, activations and features, critic values, row geometry in z), including comparisons of fake and real samples in the critic's feature space (they use only network quantities).
- **May not be used (data space):** distances, kNN/density/support statistics, moments, scales or geometry computed on raw data or on raw generator outputs (including real-only statistics on raw batches, such as a data-drift test); task/host/gate/metric information;
  constants that encode a dataset property (noise level, spacing, mode count) unless they are learned inside the game or declared as an explicit input the user supplies with the dataset.
- The critic's own input is data by construction (that is the game); using it is not a data-space statistic. Section 2's rules (clock, provenance of constants, one mechanism, ...) are process detail serving this rule; where they conflict with it, the rule wins.
- Priority: native 100-Gaussian gates first, the other toy hosts second (report both; a regression on a toy is a cost, not a veto).

## 0. Goal
One public `GANTrainer` configuration that trains indefinitely with **no learning-rate adjustment** (no schedule, no horizon, no per-task tuning), on every benchmark task, using only state-driven control and no data-space statistic (section 0.0).
"Solved" = section 4. The first hard tasks are the three native 100-Gaussian tasks (grid100, rotated100, staggered100) through the frozen noisy gates; the same config must then pass the other hosts unchanged (S3).

## 0.1 Quick start for an agent (worked examples: `gan-attempts/seqtest-20260928/` = the route-1 chain, `gan-attempts/farfield-20260928/` = a candidate built from this spec alone)
1. Read section 0.0 (the rule), sections 1-3 (labels, rules, data-space rule), 7 (what is known) and 8 (dead ends); pick a direction from section 9 or state a new one with a number, a horizon and a falsifier.
2. Make `/ml2/hypergan/gan-attempts/<topic>-<date>/`; copy `seqtest-20260928/pkg-seqC/particlegan` to `pkg-<name>/particlegan` (never edit a frozen package) and implement ONE mechanism behind one flag; keep `overrides.json`.
3. CPU checks (a minute each): parity flag-off == base (`tests/fixture.py`), step-offset, checkpoint replay, the data-space audit (section 10), `harness/admissibility_lint.py` on the `diff -ruN` patch; write `forecast.json`.
4. Run grid100, rotated100, staggered100 at 7k (section 5 command, 7-20 minutes each, two shared GPUs) and read them with `analyze.py`; screens shorter than 7k are for debugging only.
5. Fill the section 10 audit (per-rule pass/flag/violate, RULES label, ACCEPTANCE vector, status), add a ranked row to your `RESULTS.md`, ask for an independent review, and append recommended next experiments.

## 1. Vocabulary
### 1.1 Layers: classify each WRITE the diff makes
1. **Objective**: critic loss, table/generator loss, critic penalty terms (KA2), regularisers. A term computed from D's outputs/gradients is an objective change.
2. **Model law**: what the sampler draws (table rows + latent jitter + output-noise sigma; the generator map).
3. **Dynamics**: parameters written through an optimizer (AMSGrad, sparse row damping, fixed per-group multipliers, a rate or noise level that is a constant or a function of the clock only) **and** parameter moves
   off the gradient that ARE the discretised objective flow (birth/death reaction, section 3).
4. **Controller**: rates, noise levels, holds and floors written from a state statistic (a test, a ratio, a flag), even when they multiply a Dynamics group (stationarity testers, D floor, sigma floor).
5. **Readout**: how a model is read out for sampling/scoring (live iterate, EMA copy). Operational test: a change is Readout iff training state is bit-identical with and without it.
A mechanism that writes more than one layer is a bundle under A5 unless the layers are terms of one written objective/flow.

### 1.2 Base, candidate, labels, status
- **Base**: the declared package a candidate is diffed against (its sha256 is stated). Default base for the 9.x directions: `pkg-seqC` (sha256 70e7b5f5...), overrides `seqtest-20260928/overrides.json`.
  The base carries a Base Ledger (section 7.1). A chain (R against seqC, Rg against R, Rl against Rg) is audited step by step, each step with its own results row, and against the default base for the total.
- **Candidate**: a package copy that differs from its base in ONE mechanism (A5).
- **Per-rule verdict** (A0..A9): `pass` | `flag` = a required argument, test or report is absent, no code or run contradicts the rule, and it can be supplied without a new S1 run (a flag names the missing artefact) |
  `violate` = the code or a measured trace contradicts a rule condition, or the constant/mechanism was obtained in a way the rule forbids (a constant selected on S1 tasks; a data-space statistic (section 0.0);
  a clock compared with a constant; a release observed with no A7 argument).
- **RULES label** = worst per-rule verdict over the candidate's own diff and own constants (`compliant` | `flagged Ak` | `violates Ak`) plus A0 completeness of the ledger. Inherited ledger items never change the label;
  they are printed as `inherits: L1..Ln` and block SOLUTION until discharged (A0).
- **ACCEPTANCE vector** = pass/fail/pending for each of S1..S6. The label and the vector are always printed together, e.g. `FLAGGED[A2] S1 1/3`.
- **Status** (precedence top to bottom): BASE/CONTROL (declared in the README as the diff base or an attribution control; keeps its RULES label as information) > DIAGNOSTIC (violates) > FLAGGED (flagged) >
  READOUT-RESULT (declared readout as model of record, A4) > ADMISSIBLE-FAILED (compliant, an S test failed) > COMPLIANT-PENDING (compliant; S tests not all run, or ledger undischarged) > SOLUTION (compliant, S1-S6 pass, ledger discharged).

## 2. Admissibility rules
- **A0 Inheritance.** A claim covers the whole package. The base is audited once (Base Ledger); a candidate copies the ledger as `inherits`. A ledger item is discharged only by (a) a bit-identity test showing it never
  binds in the S1 tasks and at 2x horizon, (b) a state-derived replacement shipped as its own declared mechanism with a one-factor A/B (a rebase: the candidate becomes the new declared base with a shorter
  ledger), or (c) an A1/A2 argument that the quantity is stationary or derived. Items that are active by design (the KA2 warm-up, the sign-only tester) can only be discharged by (b). Every `except`/fallback branch in
  controller code is a ledger item until its taken-count is logged as zero.
- **A1 No clock, no horizon.**
  - Nothing may depend on `completed_steps`, `total_steps` or wall time. A *clock* is any quantity that is monotone non-decreasing in the number of updates unless the mechanism itself resets it: step counters, optimizer
    bias-correction or step-count counters, decision/look/event counts (any cumulative `birth_death.counters` entry), cumulative losses, path length or distance from init, ladder depth. No decision may compare a
    clock with a constant. Thresholds are allowed on quantities whose null or fixed-point law is stationary (test statistics, ratios, normalised displacements).
  - A window, lattice or cadence measured in steps passes only if (i) it is a declared sample size (a count of independent evidence units: K block pairs, one reservoir turnover of N real rows) or (ii) its length is a
    function of controller state. An evidence run length n that resets on a sign flip, a locality exit or a move is not a clock; comparing it with a minimal evidence unit (n >= 2) is allowed if the audit gives the
    null validity of that stopping rule. A window-end decision at a declared sample size is not a fallback when it is a test with a stated level and it is counted in the branch log (report early vs window-end shares).
  - *Time-dilation test* (not yet scripted: open task `harness/time_dilation.py`): multiply the table group's base lr by c in {.5, 2}, everything else fixed. Pass iff the ordered list of decision types
    (descent/hold/release) is identical and each decision's displacement-time (cumulative lr x steps) differs by less than one decision block. A candidate with no step-measured quantity says so and reports the digest test only.
  - *Step-offset test* (every candidate): on the `total_steps=None` recipe (the only legal one for continuous policies) add `10**6` to `trainer.completed_steps`; parameters after 500 CPU steps must be bit-identical to the
    unshifted run: `python seqtest/tests/test_step_offset.py <pkg> 500` (fixture `seqtest/tests/fixture.py`); identical for pkg-seqC, seqG, seqRl and pkg-far. Independence from `total_steps` is shown by dataflow (lint L1).
  - Fallbacks and timeouts are clocks: decisions taken by a fallback must be 0 in the S1 verdict window (last five checks) and < 5% overall; re-running with every fallback replaced by the null decision must leave
    the S1 verdict (pass/fail per task) unchanged.
  - Reading `completed_steps` for logging is allowed when no derived value reaches a comparison, controller, loss or optimizer (dataflow, not token match).
- **A2 No problem-specific knowledge; every constant has provenance.**
  - No reading of task names, mode centres, fixture geometry, gate thresholds or metrics, holdout/eval samples, `eval_generator`/`noise_generator`, literal seeds, or the frozen host.
  - Each constant is exactly one of: (i) a statistical level (alpha, FDR q) used ONLY for the error rate it controls; a role for Q other than an FDR level (a hold budget, a guard, a cutoff) is a new constant, flagged until a
    class (iii) or (iv) derivation from the test's null is written and a violation if none exists when the S1 runs start; (ii) derived from N, d, k or the batch size (N is one public default for all tasks or a function of the
    output dimension d only, never chosen from the number of modes); (iii) structural: derived from a symmetry, a scale-invariance argument or a fixed-point equation written in the audit (a power of two picked from a set
    of powers is a tuned constant); (iv) calibrated by a null/power criterion on a synthetic fixture that is NOT a benchmark task, shipped as `calibration.md` (fixture, criterion, grid, chosen value) with a timestamp earlier
    than the first native log (a fixture that copies benchmark geometry, e.g. a mode ring or 100 Gaussians, does not count); (v) a declared dataset input: a property of the data that cannot be learned inside the game (measured: the generator's output-noise level,
    `output_noise_std`, which collapses toward zero when learned freely and must be right within a factor ~1.5), listed in the README with the tolerance measured by running it at x.5 and x2. Keep (v) minimal.
  - Data-space scales and geometry may not be computed at all (section 0.0). Equivariance check (CPU fixture with a linear critic, not the native Fourier critic): x -> a R x, a in {.5, 2}, R a fixed rotation, leaves the sequence of decisions unchanged
    (measured for the row-evidence flags: identical for a in {.001, .5, 2}, `noout-20260928/tests/portability_sanity.py`).
  - Development/test protocol: constants may be tuned once, before the first S1 run, on the development set (everything except the three native100 tasks; leave-one-family-out for anything calibrated on more than one host family) and are then frozen in `constants.json` (sha256 in the README;
    its mtime earlier than the earliest `runs/*/job-header.json`; a run whose header postdates a change to it is a new candidate label). The base is exempt and its constants are ledger items.
    A search over constants on the S1 tasks is a seed sweep (A5). Mechanism-level revisions made after reading S1 diagnostics are allowed, but each is logged in the audit (label, date, triggering observation), counts
    against the constant budget, and any constant it introduces must be class (i)-(v) and frozen before the run that judges it.
- **A3 Information (what a mechanism may read; section 0.0 is the rule, these are its names).**
  - **N (network-internal), allowed:** losses, gradients, critic values and *features* on the training batches, optimizer state (except step counters, A1), parameter trajectories, the particles' own geometry in z, trainer state, and the real stream as seen through the critic.
    A comparison of fake and real samples in the critic's feature space (`I2f`) is N: it computes only with network quantities (reference implementation: `birth_death_space: "critic"`, section 3).
  - **I2 (data space), forbidden:** any statistic of raw data or raw generator outputs: kNN/support/density/precision-like statistics, distances, moments, scales; including real-only statistics such as a drift test on raw batches (the base's `DataDriftController` real-batch
    features are on this list: they never fired in any native run, but they are a ledger item to remove or move to critic space). Counts, flags and p-values computed from one keep its class.
  - **I3 (evaluation-side), forbidden:** gate metrics, centres, labels, thresholds, holdouts, clean/noisy scoring choices.
- **A4 Model of record / sampler.** An averaged model (EMA, iterate averaging) may be the model of record. Conditions: the config names it; its window is a function of controller state (a fixed decay is a constant); it is present from step 0; the harness must
  score it (it reads `trainer.G` / `trainer.prior` as "live": serve the average by swapping it into those parameters between steps while the fast iterate keeps training, `serve_average` in `noout-20260928/pkg-E9`; `state_dict` must save the fast iterate);
  the fast-iterate verdict is reported beside it (the training run is unchanged, so it is the same run scored unaveraged). No post-hoc change of the sampling law fitted to data (row-EM refits, reweighting, sigma refits): a quantity of the sampling law is model law
  iff the training objective or a state rule inside the loop updates it and the model of record uses it; it is a forbidden refit iff a separate procedure computes it from real data or samples and applies it at readout.
- **A5 One mechanism; deterministic single seed; no seed or constant sweeps.** A mechanism is a change that a single flag switches off with the rest of the package bit-identical (the parity test, section 5). A bundle is
  allowed only as terms of one written objective/flow, each with a one-factor ablation (an S1 run of each part, or of the base without it) and each part audited separately. A change that also alters another module's input
  (e.g. a tester scale that feeds the D floor) declares that side effect as a second mechanism; downstream shifts of existing controllers caused by the one mechanism (KA2 surprise ratio, anchor weight, alpha) are allowed and
  reported. The patch in the audit is against the declared base by sha256; a patch against another package states which mechanisms of the default base it also contains. Audit perturbations (A9, S4) are permitted once per
  candidate after the constants are frozen; their results may not feed back into any constant (changing one afterwards makes a new candidate label).
- **A6 The evaluation is frozen; the model is not.** Frozen: the harness, gates, metrics, data generators, fixtures and scoring (`harness/`, `hosts/`), and problem-specific choices made inside a host (for example the native critic's Fourier frequencies and the table size), which are listed as host inputs, not edited.
  Not frozen (section 0.0): the discriminator (architecture through wrappers inside the package, loss, penalty terms, optimizer, init), the generator, the particles/z, the trainer and its controllers, testers, birth/death, the sigma law, optimizers, the served model.
  The Base Ledger lists clocks and undeclared constants. The package under test is a copy; never edit a frozen package in place.
- **A7 Sign-only statistics (obligation).** A controller built on a sign-only statistic (cosine of displacements) has a rate-dependent fixed point and no absorbing quiet state. It must supply (a) a written argument for an
  absorbing quiet state or a bounded release rate (amplitude term, hysteresis, or an evidence bound) and (b) the ladder at 2x horizon. Without the argument the mechanism is `flagged A7`; a release observed at any S1/S1b
  horizon with no argument is `violates A7`. Inherited controllers are ledger items.
- **A8 Runs indefinitely.** No budget-exhaustion path, no reliance on a final anneal. For every hold, floor or saturating state give the state condition that releases it, its longest measured duration, and a proof or a synthetic
  run that the condition clears; a hold whose condition is fed by a cumulative counter fails A8. An absorbing quiet state satisfies A8 iff its exit is a state-evidence event (e.g. an I1b drift test at level alpha) that
  has probability <= alpha per test under a stationary stream; report the exits taken. The benchmark's 7,000 steps is a snapshot of a process that continues.
- **A9 Declared constants and the constant budget.** List every new constant with its A2 class and derivation; an undeclared constant is a violation. Report the number of non-derived constants and the stock-K3P count
  (stock = `recipes.py` defaults + `learning_rate_scales`; the count is an open item, list the constants). Numerical guards (epsilon in a log or divide, a clamp before exp) are exempt when listed with a counter showing
  they bind on < 0.1% of evaluations. Before claiming SOLUTION, each non-derived constant at x0.5 and x2 must leave every S1 verdict unchanged on at least 2 of 3 tasks and the S2 centre no worse than +.03 (the stated
  resolution of a single seed).

## 3. Data space vs network space (replaces the draft-3 I2 sink rule)
A reaction (birth/death: move a row from an over-supplied place to an under-supplied one) needs a density-ratio estimate between what the model draws and the data. In data space that needs a data-type-specific metric, so it is forbidden. In the critic's feature space it is allowed
and it works: `birth_death_space: "critic"` runs the same kNN evidence on the penultimate critic features of the table rows, the fake pool and the real reservoir (the pushforward of both laws by the same map keeps their density ratio; the measured intrinsic dimension there is 2.00),
with locality (anchor, radius, stale resets) kept in the table's own latent space; float32 shortlist plus exact float64 recompute makes it as cheap as data space. **What counts as the critic's feature space (E14, after the reviews of E11):** the concatenated inputs of every learned scalar score head (an `nn.Linear` with one output that fires in the forward pass and whose input is not the raw sample and does not contain it); a raw linear skip (`score = f(x) + w.x`) contributes nothing; a critic whose scalar heads all read the raw sample has no feature space and the estimator must refuse (E13/E14 raise an error). E11 took "the last `nn.Linear` in module order", which for two of the eight frozen host critics is the raw-sample skip, i.e. it silently ran the data-space test (vector_anisotropic). Measured (`noout-20260928`, native100, 7k live, E4-style gate + anchored release): data-space birth-death 3/3 (grid ctr .197);
none at all: rotated P, grid F (ctr .265, 11 streaked modes, mass_tv .055), staggered F (ctr .216); feature space: grid F (ctr .219), rotated P, staggered P (ctr .195), and its EMA readout passes all three.
Historical (draft 3, retired by the data-space rule): the I2 sink rule, the audit of an I2 estimator, the reference discretisation, the decoy-reservoir test (`seqtest-20260928/tests/test_decoy.py`; still a useful check that a mechanism reads nothing from the reservoir) and the critic ablation.
- **Discretisation limit and mass allocation** (measured, route 1; valid in any space): a particle reaction can birth only at existing rows, so the mean-field reaction is valid only where the model's support contains the data's support.
  While much of the table is in transit, rebirth at parent rows concentrates mass on the first modes to arrive (un-guarded, rotated100 smoke: 22/100 modes at 1,500 steps vs 100 for seq-C). And an uninformed parent
  rule (weight exp(-beta), uniform over in-support rows) is a Wright-Fisher perturbation of mode masses: staggered100 mass_tv .037 -> .096-.134 and centre .21 -> .5; rebirth at the nearest in-support row restored mass_tv.
  Any activation condition and any parent rule is a declared deviation.
- **What birth-death buys** (measured on the grid, with and without it, `analysis/mode_shape_time.py`): mass_tv .056 -> .017 within 750 steps, streaked modes (max covariance eigenvalue > 1.7) 33 -> 4 by step 1000, mean row radius .36 vs .53 sigma at the end (total width inflated by the row spread),
  centre offsets .17 vs .26 sigma. Per-mode mass errors do NOT explain the offsets or streaks (correlation ~0). The critic's mean value over a mode's rows correlates -.70 with that mode's log-mass error (slope -.45) on all three tasks: a network-internal mass signal exists.

- **Parametrisation invariance of feature-space statistics (E18; codex's audit `reports/toy100/lrfree-search/e17-feature-gauge-review`, commit 517c5e6f).** The critic function does not fix the scale (or, for a head fed by a linear map, the basis) of the features its head reads, so a Euclidean distance in the raw feature space depends on an arbitrary parametrisation: the same critic in two parametrisations gave different birth-death flags and moves. A statistic computed in the critic's feature space must be invariant to the exact symmetry group of the critic (for ReLU-type units: a positive rescaling of any hidden unit) or say which symmetry it is not invariant to. E18 divides every feature by its standard deviation on the reference half of the real reservoir (a function of the reference half only, so split-conformal validity is untouched; units without spread are dropped). Whitening is invariant to more but amplifies low-variance directions and makes the pseudo-inverse floor gauge dependent; on the native critic the raw metric loses recall (.91 -> .61) only at a 16x random rescaling, but on the toy critics the raw metric is dominated by a few units (the 8 largest of 128 features carry 42% of the squared distance on img_bars4) and standardisation alone takes the suite from 10/13 to 13/13.

## 4. Acceptance tests ("solved")
Frozen gate thresholds (`analyze.py` COV/ACC/hold_ok, `harness/native_failmodes.py`): terminal check = modes = 100, precision >= .97, min HQ mode mass >= .005, max mode mass <= .02, mass_tv <= .10, min cov-eig ratio >= .40,
max cov-eig ratio <= 1.70, radial median ratio in [.65, 1.40], and accuracy: mass_tv <= .06, centre RMS <= .20 sigma, |cov trace bias| <= .10, radial KS <= .04; holdout (100k): precision >= .97, centre <= .20,
|trace| <= .10, KS <= .04, mass_tv <= .06. The verdict is the five-check verdict at the last five 250-step checkpoints of each 7,000-step multiple (the harness scores every multiple as its own budget) plus the holdout.
- **S1 native100** (frozen noisy gates, QR init): grid100, rotated100, staggered100 all PASS at 7,000 updates.
  **S1b sustained:** the same three PASS at `native_steps=14000`. *Release* = a rise of a discrete tester scale s of any group (table, network, sigma) or of the D-floor term max(s_D, .75 s_prior) evaluated on tester scales
  only, i.e. a step of ratio >= 1.5 in `rates.jsonl` after that group's last descent; the continuous critic payoff-damping factor (which moves the critic's raw lr on most steps) is not a release. No release in
  [7,000, 14,000] is evidence, not proof (A7 carries the burden beyond 14k); a final candidate also gets a 28k run.
- **S2 margin** (a single deterministic seed is a coin flip near the edge; centre effects < .03 are not resolvable): report the holdout-deconvolved centre x_hat = sqrt(holdout^2 - .0435^2) (.0435 = sqrt(2/1000): the holdout centre RMS of
  a perfect model at 100k draws, 1,000 per mode; the terminal-check floor at 20k draws, 200 per mode, is sqrt(2/200) = .0984 +/- .0049; a perfect model's precision is 1 - exp(-4.5) = .9889, the mass within 3 sigma), holdout precision, and headroom in oracle SD. Classes:
  FULL margin = x_hat <= .16 on every task (a design margin: a single 20k check needs true offset <= sqrt(.20^2 - .0984^2) = .174, and .16 is what five checks tolerate) and precision >= .973 on rotated/staggered;
  otherwise THIN (printed with the label; allowed for SOLUTION). seq-G is THIN on grid (x_hat .165).
- **S3 portability (the headline test of the rule):** the same config, unchanged, on the other hosts: `harness/submit.py --cand NAME --package-root DIR --overrides FILE --tasks all --candidate-options '{"eval_output_noise": true}'` (preset `gates` = mode_hold + 4 image + 6 vector = 11 tasks; `all` adds
  ring_shift + stationary = the 13 gates; `all22` = gates + the 8 custom22 hosts + the 3 native tasks). Report per task against the base; a regression on a toy is a cost, native100 has priority (0.0). The 8 custom22 hosts ERROR for the base (a harness refusal on critic input noise, not a model result).
  Reference: E4 (`e4-noout-fullsuite`, run by codex) passes 11 of the 13 (img_bars4 and img_intensity2 fail, exactly as the base and the archived lineage do); E11 (`E11-noout-13gates`) passed 12 of 13, but with code whose drift statistic was live on ring_shift and whose critic-space birth-death ran on raw samples for vector_anisotropic (RESULTS 0.5); **E14s (`E14s-gates`, `E14s-va`) passes 10 of 13** (img_bars4, img_intensity2 5/24 and vector_unequal_mass fail; the last two are chaotic single-seed flips on tiny tables, RESULTS 0.4); **E19a (`E19a-gates`) passes 13 of 13** (img_bars4 17/24, img_intensity2 16/24 and vector_unequal_mass 20/24 pass for the first time in this lineage; the support test is inert on those tables, the feature scale is the only relevant change; those three were real failures, not bad tests: an ideal 256-row table passes vector_unequal_mass 99.8% of the time); E20a (a variant with p-weighted parents) fails ring_shift (239/460, hq 0.89-0.92 against 0.90) and E21a fails it too (a collapse episode at step ~4140): the shift gate is flaky in this lineage (RESULTS 00.4). ## 6. Failure-mode taxonomy (diagnose with numbers, not pictures)
Definitions: *clean cloud* = the table rows without output noise; a *stray* = a clean-cloud row more than 3 x .03 (observation sigma) from every true centre (3 sigma is for measurement only; a mechanism may not read
centres, A2). Diagnostic-only geometry: `analysis/forensics/lib.py` (`centers`, `assign`; hard-codes the task geometry).
| mode | signature | how to measure |
|---|---|---|
| STRAYS | stray fraction > ~.015; holdout precision vs stray fraction on rotated: .0115 -> .9755, .0121 -> .9750, .0168 -> .9727, .0192 -> .9694, .0206 -> .9545 (with releases); 5.6% at step 1000 | clean-cloud stray fraction |
| JITTER | coherent per-mode offset .13-.25 sigma (rms over modes; per-mode random, not affine) wobbling on 250-1000 steps | holdout-deconvolved centre; live vs EMA gap; per-mode mean offsets |
| BREATHING | live trace/KS/eig swing between checkpoints at a high table rate | last-5 trace range |
| RELEASE | a table or network rate scale rises after descending (chatter, cascades) | ladder from `rates.jsonl` |
| STREAK | max covariance-eig ratio > 1.70 on one mode | `metrics.jsonl` max_cov_eig_ratio |
| MISSING_MODE | modes < 100 or HQ mass < .005 | `metrics.jsonl` |
Established mechanism: stray rows sit where the critic is flat (|grad D| ~ .004-.009; the gradient points at the nearest mode with cos +.17 on rotated, ~0 on staggered), so lowering the table rate freezes them
(drift = lr x s x signal-to-noise, thousands of steps) and their persistent motion re-opens the rate (release). One scalar rate cannot serve strays and the settled bulk. The AMSGrad state does not
single strays out (sqrt(v_max) and sqrt(v)/sqrt(v_max) are alike for strays and bulk on saved states). Native100 host critic: `SimpleMLPDiscriminator(2, 128x3)` with Fourier features (pi 2^k) + raw x, LeakyReLU (frozen).
Table optimizer: `K3PGeneratorAdam(latent_table=...)` (`recipes.py:342-344`, `k3p.py`), AMSGrad per row with sparse touches (a row is touched about batch/N of the steps); the tester scales come from `continuous.py`.
Measured anatomy (noout-20260928, `design/FACTS.md`, rotated100 unless stated): batch 2048 of 20,000 rows (a row is touched every ~10 steps, ~680 touches per 7k run), per-touch step ~.3 sigma at s=1; the critic is flat (values +-.01) and cannot see an individual stray (weight 1/B).
STRAYS are mostly evaporated rows: only 22-28% of the final strays were never captured, 72-78% left a mode after step 2000 (in seq-C 36 of 58 late departures fall in the tester's releases; displacements are gradient-limited); the critic's inward force on strays is weak (+.0016..+.0046 vs |F| .005-.010).
RELEASES are a bulk effect: the row-mean block cosine is positive at the short scale as the rate falls (+.03..+.05, t up to +10 over 20,000 rows) and only marginally negative at the long scale; mean/median/trimmed aggregates and excluding oracle strays change nothing.
JITTER: the per-mode restoring signal for a .15 sigma offset is .13-.33 of the noise of the mode-mean critic force per 125 steps; the ladder is the only lever. A row's own gradient history (Hotelling T^2, window ~50 touches) separates current strays from the bulk with AUC .91-.95 but not future leavers (.45-.64).
The generator's output noise (`output_noise_std` .029, the data's own noise level) is a dataset input: learned freely it collapses toward zero from every start (.029 -> .004 in 3,000 steps, .06 and .015 shrink proportionally: the critic always prefers the peak), and the recipe only works within about a factor 1.5 of the right value
(x2 too wide: precision .67; x.5: centres .23-.31, shape fails). Averaging: mean-reverting mode jitter is reduced by averaging the served model over ~4 table-tester blocks (~1,000 steps late in the run; centre offsets grid .170 -> .142, rotated .252 -> .119 offline, no extra strays); windows of 2,000+ steps smear strays.

## 9. Open directions (formulation-level; each states a number, a horizon and a falsifier)
1. **Reaction in network space, better.** E7's feature-space birth-death is a little less accurate than the data-space one (centres +.013-.022 sigma, grid live F). Options: a mass-transfer reaction driven by the critic's mode-level value (r = -.70 with the mode's log-mass), row weights instead of teleports (no transit, no jitter),
   a cheaper evaluation cadence. Prediction: live grid centre <= .19 without the averaged readout; refuted if any S1 task fails or mass_tv > .05.
2. **Amplitude-aware annealing / learning-rate robustness (S4).** The sign-only ladder is not lr-equivariant (x1.33 base lr: E4 0/3, seq-G 1/3, seq-C 2/3). An averaged served model is lr-equivariant in theory (variance xi^2/(k^2 L) independent of the step for L >> 1/(eta k)) and E11's S4 confirms it (6/6).
   Derive the window constant m (now 4 tester blocks = the smallest window that halves a mean-reverting jitter's variance) instead of declaring it; decide whether a target jitter amplitude can be defined without data scales.
3. **Noise level as an input.** Learning it freely collapses; derive it (a critic-feature moment match, or the particles' own cell size std(z) N^(-1/d) times a learned factor) or keep it a declared input with a measured tolerance.
4. **Data-space leftovers and a shift trigger.** The real-batch drift statistic is removed from the executed path (E12); what remains is a *network-internal* trigger for a distribution shift on a settled table (the ladder needs 6-12k steps to release without it): candidates are a two-sample test between an old reservoir of reals and the current batch, both mapped through the same current critic (exact null under stationarity, drift of the critic cancels), or the flagged fraction of the row-evidence gate exceeding one half. Falsifier: a native100 run with a data shift at step 4,000 that does not re-arrive within 2,000 steps, or any false trigger on a stationary run. Audit every remaining computation on raw data or raw generator outputs (section 10).
