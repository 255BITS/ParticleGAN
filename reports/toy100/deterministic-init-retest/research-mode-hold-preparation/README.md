# Research KA2 initialization port preparation

This is a source-prepared, unexecuted route to retest the original asymmetric-Kalman research KA2 on the1200-step tiny host. It preserves the exact research mechanism, latent/response hooks, loss, schedule, original eager-CUDA Adam metadata policy and frozen custom loop. It does not substitute public KA2 or inherit research22/22.

`source-plan.json` pins the KA2 files, shared parent probe, historical runtime, host, new public initializer package and declared policy. `initialization_bridge.py` changes only the fresh prior/model constructor boundary in the exact old host. The reverse transform recovers the full original function byte-for-byte. The bridge calls actual new Recipe.make_prior with a scoped binding to the old prior class, retaining its original Gaussian draw and research registration, then initializes G/D with standalone public keys0/1. Old tensor fixtures are prohibited. The global optimizer-index initializer used by some historical research reports is not installed.

The dense tiny host has no batch-distance discriminator. The bridge rejects a batch-distance/custom head; broader hosts need explicit old/new class mapping and initial batch-head zero proof. Same initializer family does not prove identical initial tensors. An independent constructor-only proof must compare every G/D/prior parameter and buffer against the reviewed public tiny host, check repeated builds without RNG reset, confirm unchanged original caller cursor and no additional initializer RNG draws, verify prior registration, and exercise exception restoration. These checks have NOT_RUN. No training or GPU work was done in preparing this bundle.

`run_research_mode_hold.py` refuses to proceed without a matching independent CPU receipt containing all required checks. Once the supervisor reviews that receipt, one external worker can run it with `--reviewed-cpu-proof PATH --output NEW_DIRECTORY`. The wrapper scopes serial autograd across the complete original probe and retains raw new initialization tensors and source identity. Its output remains RESEARCH_HOST evidence, not a public-GANTrainer score. The original probe's full1200 budget,24 observations, final-five gate, eight-mode/HQ.9 thresholds and120/240 noise milestones remain intact. Preserve schedule in the first retest; scheduled quality does not qualify run-forever behavior.

For other historical candidates, first establish their exact local mechanism/config/latent/response and original probe/runtime binding from the full inventory. Reuse this constructor adapter only when the entire frozen host function and primitive prior contract match. Candidate-specific dynamic prior geometry or custom models require separate initialization review. Do not overwrite missing source bindings with a nearby alias or inherit passes.

The runner requires Torch2.13.0+cu126, CUDA12.6 and an NVIDIA RTX A6000, with deterministic algorithms, TF32 disabled, one thread, full serial autograd and CUBLAS `:4096:8`. The historical research path keeps CUDA as its default device and its original eager CUDA Adam counters; this is explicitly different from the public host. Bytecode writes are disabled before imports. Each executed output retains the full prepared source snapshot and independent CPU proof in `prepared-source.zip`, alongside the actual runtime receipt.
