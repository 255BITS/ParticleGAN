# Output-noise RNG audit

The current output-noise implementation draws from PyTorch's global RNG: `OutputNoise.forward` in `benchmarks/toy100/models.py` and `NoisePolicy.output` in `benchmarks/transfer_suite/legacy_noise_adapters.py` both use `torch.randn_like` without a generator. Discriminator input noise uses a separate seeded stream. Checkpoint measurements fork and restore the global RNG, so evaluation frequency does not cause the training-stream shift described below.

Six of the 22 hosts also use the global RNG for training data or latent draws:

- All four image hosts (`img_stripes2`, `img_bars4`, `img_blobs4`, `img_intensity2`) draw real template indices and real jitter globally in `run_image`; their `GANTrainer` is given `torch.default_generator` for latent sampling. D-side output noise therefore changes the G-side latent draw within the same update and later real batches. `setup_image` also calls `torch.manual_seed(0)` **only when output noise is nonzero** after network and prior initialization. Thus a zero-noise comparison differs from the first real batch even though the positive-noise warmup makes the first update's output sigma zero.
- `ae_gan_hold` draws real data in `sample_data`, prior samples, and encoder samples from the global RNG. The noisy decoder forward changes subsequent draws, including within an update.
- `cover_leftover` draws real clouds, prior indices, and particle jitter globally. D-side output noise changes the later G-side `fake_batch` and future real clouds.

The other seven legacy hosts use fixed data/latents or explicit generators for their stochastic training draws under the current `b_cap` recipe. The six vector hosts and three 100-mode problems use explicit data, latent, and penalty streams. These hosts still draw output noise globally, but that does not redirect another training data or latent stream in the current loops. An interpolation penalty using an implicit global generator would need its own audit if the regularizer arm changed.

This is a limitation of **same-seed zero-noise versus positive-noise attribution** on the six affected hosts: those runs are not paired-data ablations. It does not invalidate their saved frozen gates or imply that the observed model results are false. The current κ, learning-rate, and prior-regularization searches all retain fixed positive output sigma `0.029`, warmup `0.2`, architecture, and update loop. `OutputNoise.forward` draws whenever scheduled `std` is positive, regardless of κ, rate, prior-reg weight, or model values; `b_cap` adds no random interpolation draw. Assuming runs complete the same steps, their output-noise call counts and global draw sequence remain paired with respect to those policy changes. Comparisons that change output-noise onset or disable it do not have that property.

A future uniform isolation rule would give output noise a dedicated, seeded `torch.Generator` on all 22 hosts and remove the image-only global reset. Native `GANTrainer.sample`, transfer vector/image measurements, and legacy `NoisePolicy.evaluation` would save/reset/restore that stream so live and EMA checks use paired draws without advancing training. `GANTrainer` checkpoints would record and restore the new stream alongside existing RNG states. That is a numerical algorithm change and would require fresh 22-host training evidence; it is not a regrade-only correction to the current runs.
