# Optimistic Adam scratch screen

The six predeclared Optimistic Adam rows all failed the ordered older-host screen. None qualified for a fresh full-19 replay or native 100-mode training. The durable evidence directory (`artifacts/toy100-accuracy/optimistic-adam-six-v3-d6917ba`) contains all 13 attempted episodes, their frozen curves and source archives, the six-row manifest, application receipts, logs, independent regrade, and skipped-host lists. The scratch source epoch is `d6917bac1605738d2e4cff70f1f3fea941b7678a`; the predeclared manifest SHA-256 is `4000496251cf9803cfb94fc1b4c873e27d9d3bdd3594664d746bce749c7ea6b8`.

The adapter applies the direction from Algorithm 1 of [Daskalakis et al., *Training GANs with Optimism*](https://arxiv.org/pdf/1711.00141), `θ ← θ − lr_t[(1+α)u_t − αu_(t−1)]`, with the previous bias-corrected Adam direction initialized to zero. The previous direction is stored *without* an LR factor, so both terms use the current scheduled rate. `α=1` uses the paper's optimism coefficient; `.25` and `.5` are experimental damping. The paper analyzes different game and update assumptions; these hosts retain their existing alternating D/G/prior loop and losses, so its convergence result is not being claimed here. No extra gradient evaluation, data draw, threshold change, or host-specific setting was introduced. The recent [late-grid diagnosis](grid-center-optimizer-diagnosis.md) found a measurable live–EMA lag but no resolved cycle in five terminal checks; this screen tests an optimizer hypothesis, not a demonstrated cycling fix.

A row stopped at its first strict non-PASS; skipped hosts were **not** counted as failures or tested. All attempted hosts used their frozen seed 0, budgets, architecture, resource limits, and live-weight sustained-success gate.

The first row was run alone as a harness smoke before continuing. It completed 400 trajectory steps with two intercepted Adam optimizers, 800 actual optimizer calls, and 5,200 parameter-tensor update events. Across all 13 attempted episodes, the scratch regrader checked every optimizer group size and every applied LR against the declared role and schedule, the saved previous-direction state and update counts, the frozen host verdict and 24-checkpoint curve, the full executable-source archive, and exact adapter/driver/regrader hashes against the manifest. It rejected copied evidence with a missing receipt, altered adapter source, altered binding, and an ordinary/no-receipt episode. The production common gate independently returns **INVALID** for these scratch episodes because they declare an unsupported optimizer; the gate guard is in separate commits `798f912` and `a15a4e5`. Twelve focused adapter/regrader tests pass. The retained 13 episodes were regraded again after byte-for-byte copying from RAM.

The earlier v1 and v2 scratch epochs are **harness-invalid**: v1 stopped before host construction because the file-path driver lacked its worktree on `sys.path`; v2 trained hosts but failed to load the raw result from the summary index and produced no optimizer application receipt. Their observed curves were excluded from this screen. Only the v3 episodes above are optimizer evidence, and they do not support promoting Optimistic Adam under either declared shared core.
