DV16 needs a library-owned component update before any of the eight custom hosts can run faithfully. Its existing optimizer and penalty factories are useful, but do not execute its controller observations, learned latent support, antithetic shape-gradient pass, noise, EMAs or complete checkpoint. This review supplies a concrete binding plan, not an implementation or qualification claim. No Torch import, model execution, training, GPU work or active-candidate edit occurred.

DV16 is an ordinary D-then-G update with adaptive rates. It has no RP5 precision controller, predictor/corrector, secant fit or eager-Adam mode. The RP5 component transaction is a design reference only; importing its arithmetic would create another learner. The DV7 role-aware LR-helper patch is already incorporated and extended through DV16. The RP5 conditional precision probe is unnecessary here: DV16's data detector observes real tensors, not a live/reference input-gradient gap. The existing paired KA2 penalty already supports conditional module views.

The minimal public boundary is a component trainer taking an ordered registry of real modules/standalone parameters, G-side optimizer bindings, one critic root, zero or more named latent sources, complete objective callbacks, and caller-owned context/RNG state. Callbacks return separate adversarial, penalty and auxiliary expressions; they cannot step optimizers, change rates, advance the controller or read evaluator scores/budgets. The library owns this exact DV16 ordering:

1. Observe prior geometry, then previous KA2 surprise, then current real data once. Set G rates to `base * network`, every prior-owned group to `base * prior_scale`, and D rates to `(base * network) * critic_scale`. Never compound already-scaled rates.
2. Compute D fakes with the declared latent/output-noise sites. Compute the original complete D objective and ordered KA2 calls, then one native critic step. DV16's `observe_support` and `observe_pair` are no-ops; do not resurrect DV11/8 logic.
3. Freeze critic gradients, compute the complete G objective, and perform the ordinary backward. Capture exactly the G sampling/noise state needed for the opposite-support evaluation. That evaluation changes only the compact-support sign and updates only width/shear gradients; it reads no additional real batch and commits no extra buffers or global/training RNG movement.
4. Observe generator/payoff once using the adversarial G and D losses, excluding penalty and auxiliary terms; step the registered G-side optimizers once each. Restore critic flags, update declared EMAs, and advance one completed-update clock. Keep the entire higher-order backward scope inside serial mode.

Keep the existing single-prior `GANTrainer._step` path intact initially. A new component route must dispatch its ordinary binding through the unchanged path until numerical, RNG and checkpoint parity is demonstrated. Sharing helpers later requires evidence; unchanged constants alone are insufficient. Existing 11 host scores belong to the immutable package, not automatically to an extension.

Four bindings require explicit review:

- **Multiple or absent latent sources.** `DataDriftController.latent_bandwidth` is one vector, initialized/updated by `observe_prior`; sequentially observing two priors blends unrelated geometries. Add named support state with one unchanged `std(z) * N**(-1/d)` initialization and .01 update per real source, once per accepted update. Keep global mobility/game/payoff evidence shared. The ordinary one-source path retains its exact storage/arithmetic. A no-prior host omits this nonexistent branch structurally, while retaining the complete controller/KA2 update. Never pass a fabricated table. Two existing `make_generator_optimizer(..., latent_table=z)` instances can own the two z histories; width and shear each retain their own ordinary prior-rate Adam group. Do not concatenate nonleaf tables or damp shape parameters as A2 rows. Explicit prior-role parameter membership also covers the direct-particle tensor; the present helper's `prior.parameters()` argument alone does not describe that tensor.
- **Auxiliary versus antithetic shape gradients.** Current `training.py:295–304` averages the complete forward width/shear `.grad` with a reverse *adversarial-only* gradient. Its ordinary prior regularizer depends only on z, so this is correct there. For a custom loss where generated cover/reconstruction depends on shape, copying it would yield `0.5*(adv_forward + aux + adv_reverse)`, halving aux. Preserve `0.5*(adv_forward + adv_reverse) + aux`; capture the adversarial shape contribution separately and keep the complete ordinary G/z/encoder/embedding gradient. This is a required new contract, not existing tested behavior. The reverse expression must reproduce the complete weighted adversarial objective across its original fake sites. Pair only DV16's compact support, keeping host MoG noise/jitter, conditions, real scores and output-noise draws fixed. The current fork restores global RNG after the opposite pass but does not rewind global stochastic-module draws to the original forward; the copied frozen models have no dropout. A broader stochastic-module promise would need separate semantics and evidence.
- **Conditional and multirole evidence.** `_FastView` must register the paired critic child and carry the current slow tensor; KA2 then substitutes its actual EMA counterpart. Scale views call `score(normalized, scale)` for penalty, preserving raw-unit input/output sites. Do not pass the original bare lambdas to the identity-checking paired API. Observe real data once per accepted update, not once per role. A minimal proposed multirole rule is one fixed-order concatenation of the role real batches, in the actual raw data coordinates and original multiplicities; the one-role path is unchanged. This is a declared extension choice, not a previously qualified aggregation. Do not mix condition labels into penalty differentiation or borrow RP5 gradient-gap averaging. KA2 applied-call clocks retain two/four calls per D step; its optimizer/EMA clock remains one. Thus first blend at call 800 occurs during update 400/200 for those two/four-role hosts.
- **MoG and encoded AE support.** `make_prior(prior_kind='mog')` creates no `log_width` or `shape_shear`; `perturb_latent` requires them. `particle_ae` does expose hard selected indices with a soft straight-through derivative, so missing indices are not the blocker. The unresolved choice is how DV16 compact cells compose with standardized means, the existing fixed Gaussian sigma and deterministic `center + bounded_offset` reconstruction. Raw-z bandwidth and standardized-code bandwidth have different units. An implementation must declare the coordinate convention, whether sampled and encoded sites both receive support, how opposite evaluations preserve Gaussian/offset draws, and which auxiliary shape gradients survive. Adding shape fields alone does not answer these questions. Retain the MoG and routing architecture; do not substitute a plain prior or silently disable DV16 support. This is the clearest gate before claiming all eight are covered.
