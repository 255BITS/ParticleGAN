This is a source-only proposal for a reusable RP5 component transaction. It contains no engine implementation, applied patch, CPU execution, training, or quality claim. The unchanged candidate must survive its existing gates before any integration is considered for release.

All15 active package files still match the immutable `rp5-single/source.zip` (SHA256 `43eaad25848e65605afc08b39ff2b714277e0d792315dcb5f5b6f49a25263df7`). `reference-source/` contains those exact bytes; `reference-host/` contains the frozen custom-host sources, and `source-audit.json` pins both. The existing custom22 preparation map is sound: none of these eight hosts fits the current `GANTrainer` faithfully without an integration extension.

`component_interface.pyi` makes the proposed boundary concrete. Add one library-owned `ComponentTrainer`; make ordinary `GANTrainer` a binding to the same internal transaction only after parity is established. The caller registers actual modules, standalone parameters, loss expressions, conditional views, current batches and auxiliary state. The library constructs the declared recipe optimizers and owns rates/noise, backward, predictor rollback, secant acceptance, KA2 state, precision, EMAs, accepted clocks and checkpoints. Loss callbacks cannot perform optimizer/controller steps or change rates. No artificial identity generator or unused particle table is required.

The minimum surface needs one critic root, an ordered sequence of G-side optimizers, and one complete D-loss/G-loss pair. All eight hosts use one critic; multiple scales contribute to that same critic's loss, not separate controllers or accepted steps. Support multiple G-side optimizers because two independent latent tables need their own existing A2 histories. This does not require inventing a new optimizer algorithm.

The ordinary binding must retain the exact current parameter lists and order: critic parameters, then generator followed by prior parameters. Do not silently switch to sorted names or omit currently included frozen parameters from the secant lists. Preserve the existing single G optimizer containing its generator/prior groups. New component registries name parameters for validation/checkpointing; names must not change numerical order. Reject overlap across optimized roles, repeated parameter ownership, mixed rate roles within a group, and unregistered trainable tensors.

The accepted transaction must follow the existing `game_update.py` implementation:

1. Resolve exogenous caller data once. Current `joint_step` materializes `generator_real` before its trainer checkpoint; the ordinary binding must preserve that placement and draw order. Registered caller cursors define the boundary for custom hosts explicitly.
2. Save the complete accepted state and ordered base parameters. Read RP5 scales and package noise amplitudes at the current accepted clock.
3. Evaluate the base D field; run its existing backward, stage swap, optimizer step, and restore D to the shared base state before evaluating the G field. Compute the complete G gradient before stepping any G-side optimizer.
4. Save predictor parameters and base-field optimizer states. Restore all nonparameter state and RNG streams before the corrector. Recompute G/encoder/routing outputs at predicted parameters; never reuse cached predictor outputs or encoded latent values. Reuse exogenous data/context and restored random choices.
5. Evaluate the corrector with the same role/loss order. After restoring critic flags, apply the unchanged `secant_resolvent` once over the concatenation of all D and G-side parameters. Restore the saved base-gradient optimizer states, then perform the exact accepted KA2 reference reseed/update handling. Predictor/corrector previews must not double accepted counters or penalty-call history.
6. Update the declared generator EMAs in their existing parameter/buffer arithmetic and order. Advance the accepted update clock once. Compute the accepted activity and conditional precision evidence once, updating its reference and controller once. Preserve the current ordinary ordering: `_ordinary_step` advances completed_steps before `joint_step` observes precision.

The whole transaction, including higher-order penalty creation and precision gradients, stays inside `serial_backward`. Retain native RP5 eager-Adam semantics, the same noise bootstrap360/720, base-gradient moments, KA2 penalty/anchor arithmetic, and the exact secant formula. There is no evaluator budget, target-change notification, metric-based phase switch, or replacement controller in this proposal.

For multiple G-side optimizers, activity is one RMS over the concatenated `(accepted_parameter - base_parameter) / applied_group_lr` values, in declared optimizer/group/parameter order, with the existing grad-present mask. Do not average per-optimizer RMS values. The current one-optimizer route must dispatch through its original reduction so its ATen operations remain identical. Each optimizer gets one step per field, but the learner accepts one joint update. Keep all base-field optimizer states for the accepted state. Critic anchor handling occurs once for the shared critic.

The two ownership issues can be made explicit:

- **Direct particles:** frozen `compare_defaults.py:131–147` marks `opt_p` as prior-rate-owned. `two_pole` therefore registers the real particle parameter directly, uses the existing direct-particle response, and assigns the prior rate role (`lr * prior_lr_mult`, then RP5's prior scale). It has no sampled latent prior and no A2 latent-table binding. The direct-response beta/gain behavior remains the recipe's declared public behavior. Assigning ordinary generator LR would alter the frozen comparison binding.
- **Two tables:** `cover_leftover` retains separate positive/negative tables. Use the existing `make_generator_optimizer(..., latent_table=table)` separately for each table, plus the residual's G optimizer, all within the same G transaction. Each table is alone in its prior-rate group and owns an independent A2 history. The original joint spread expression over both tables remains a single loss term; concatenating values for that loss is valid, concatenating nonleaf tensors as a fake optimizer table is not. This binding needs its own order/state parity contracts before use.

The existing [conditional-probe support](../rp5-conditional-probe/README.md) supplies a narrow `probe(module, data)` hook and has separate CPU evidence. Reuse it for one conditional role. The callback must evaluate the supplied live or precision-reference critic, close over the current fixed condition, and differentiate only the data tensor. A closure permanently bound to live D would erase the intended disagreement.

Multiple scale roles need one additional reviewed primitive, such as `observe_roles(critic, probes, activity)`. Compute every live/reference gradient gap before updating the shared reference. Aggregate squared gradient differences by total data-coordinate elements: `sum_r ||g_r - ref_r||² / sum_r numel(real_r)`. The scale hosts have equal shapes, so this is equal role weighting. Then update the reference once and call the existing `advance(gap, activity)` once. Keep the original single-role `observe` path unchanged. Calling `observe` once per role would change the temporal constants and give later roles a different reference. This aggregation is a proposed extension requiring analytic CPU contracts, not previously qualified RP5 behavior.

Penalty and precision coordinates differ for the scale hosts. Their penalty differentiates `critic.score(z, scale)` in normalized coordinates, while precision must use the raw-data `critic(real, scale)` convention. Preserve raw-unit input noise exactly once before converting back to normalized coordinates. For slow/fast hosts, `_FastView` differentiates only fast coordinates and carries slow context unchanged. Use an `nn.Module` view with the actual paired critic as its registered child for the public paired penalty; a bare lambda is not a substitute for its identity/EMA mapping.

Preserve the **resolved** frozen auxiliary coefficients. `compare_defaults.candidate` sets particle_l20 and maps VICReg to recipe.prior_reg (RP5 is0); baseline cover_weight1.5 and independent reconstruction/residual/hold terms still survive. Retain expressions and emit their resolved coefficients. Do not revive raw-host .02/.05 defaults or drop nonzero auxiliary objectives. No current score or task name should be used to reconstruct those objectives; the copied source functions are the authority.

A component checkpoint needs a new versioned envelope with immutable binding identity, ordered module/standalone-parameter names, optimizer/group memberships and rate roles, recipe/options, serial mode, dtype/device, model tensors/buffers, all optimizer states/histories, KA2 critic reference and counters, precision state/reference, declared EMAs, global/private/caller RNGs, caller data cursor, conditional context state, per-module modes, requires-grad flags, and gradient buffers for exception rollback. Validate the complete topology and every state before mutation. Callables are never pickled: restore must supply the same binding identity and reconstruct callbacks/current context. The existing scalar `GANTrainer` checkpoint projection remains supported unchanged; a broader registry cannot be silently stuffed into its fixed G/D/prior schema.

The current implementation already saves optimizer/model/global/private RNG state, but its fixed registry does not cover arbitrary host objects, module mode flags or gradient buffers. Custom transaction rollback must make that ownership explicit. Keep two boundaries clear: a prepared batch may already have advanced the caller's data cursor; rollback restores the declared accepted transaction entry, not an undocumented earlier point before data acquisition. Mid-stage resume is out of scope; checkpoint accepted boundaries only.

Before any custom quality run, the bounded CPU contract work is:

- Existing scalar-GAN byte/ATen/checkpoint parity, including open/closed precision states and exact accepted clocks, optimizer histories, KA2/EMA/RNG state and loss values.
- Multi-optimizer joint secant/activity equality and independent two-table A2 histories; direct-particle prior rate ownership and absent fake prior.
- Predictor/corrector replay of exogenous draws, with parameter-dependent routing recomputed; no duplicated data consumption or lost auxiliary gradients.
- Analytic conditioned multi-role gradient gaps, one reference/controller update, and accepted KA2 call counts for two/four roles.
- Failure injection at D/G/acceptance boundaries, complete state restoration, and checkpoint rejection for changed role/loss/source/execution identities before any mutation.

A transaction extraction touches the hot path, rollback registry, multi-role evidence and optimizer ownership together. An unapplied speculative implementation would not establish parity. This deliverable therefore stops at a concrete typed API, pinned source, binding decisions and validation plan. The eight custom scores remain NOT_RUN; no ancestor quality result supplies them.
