## Mechanism distinctness and actual rate meaning

C10 starts from immutable C7 rather than inheriting C9's local backtracking. It changes only `particlegan/game_update.py` and recipe validation. For each native proposal role D/G/prior, it computes a scale equal to that role's current proposal L2 norm, floored at1e-12. It divides both same-oracle fields by those scales, fits one shared dissipative/rotational response plane, then unscales the accepted result. The scaling is recomputed from the current proposal each update; there is no carried radius or evaluator-derived signal. This is a substantive change in the metric used by the resolver. It does not force identical rolewise damping: a shared fit can give different accepted/native ratios to each role.

C11 again changes only `game_update.py` and recipe validation. It retains the same joint predictor, but solves one separate secant plane for D, one for G and one for prior. The fields remain coupled through their evaluation at the same joint predicted parameters; only the fitted response is separated. Consequently another role no longer supplies its response denominator. The original resolver is a fitted model, not a proof of nonlinear GAN convergence.

Every C10/C11 ring and image receipt keeps public G/D LR=.00425 and prior LR=.0085, with two native joint field evaluations per accepted update. Accepted displacements vary with the fitted response. For C10 ring, the observed accepted/native norm ratios span D .00853–.72787, G .02081–.86557 and prior .01169–.68521. C10 image ratios differ by role too; D reaches .84650. These are constant nominal optimizer rates with adaptive accepted displacement, not fixed-size updates or ordinary Adam at those rates alone.

The public `make_recipe` ignores evaluator `steps`; `GANTrainer.step` owns the complete transaction. Neither future target change times nor quality/evaluator results enter the correction. Fixed360/720 noise startup and799 initial pure-A penalty calls remain the declared, age-based learner initialization, never restarted at the target change.

## Public API findings

C10 retains the earlier staged optimizer-hook limitation: hooks execute for both native stages, and state-load hooks can also repeat during rewind. The submitted hosts register none. C11 addresses this optimizer-hook boundary by rejecting global optimizer pre/post hooks and registered optimizer step/state-dict/load-state-dict hooks **before** evaluating a generator-real callable or taking the snapshot. The referenced registries exist in the pinned installed Torch source. Side effects can instead run after the public step returns. This is an actual API contract improvement; it does not make arbitrary module hooks or external Python state transactional.

Both numerical methods are installed by `GANTrainer.step`, not by optimizer factories alone. The trainer still explicitly accepts only scalar unconditional GANs, an exact ParticlePrior and no encoder. Its role lists are D and G+prior, with no generic multi-critic or auxiliary-loss closure. Conditional, MoG, encoder and custom-loss hosts need a faithful public transaction extension; using the native factories alone would omit the candidate mechanism. The source explicitly documents this narrower scope.

Managed tensor/optimizer/reference/EMA/PyTorch RNG state remains owned by the transaction. Caller data state, arbitrary Python attributes and external generators remain caller-owned. Final correction buffers/RNG supply continuation, and checkpoint recipes/execution mode must match. No broader replay guarantee is inferred.

## C12 source review and early scope

C12 now has its own immutable declaration/source. It adds `checked_game.py` and changes only recipe validation and trainer dispatch; native kernels, C11 optimizer-hook rejection and the underlying coupled secant resolver remain unchanged. `checked_secant_step` starts each update at numerical fraction1, evaluates the native field at the fraction-scaled predictor, and fits the coupled response using fraction-scaled fields. It then performs an additional same-oracle field evaluation at the proposed accepted point. For each D/G/prior role separately, it requires `||delta - fraction*F(x+delta)|| / ||delta|| <= .5`, using a numerical denominator floor1e-30. Failure halves the transient fraction and recomputes both fields, with16 allowed backtracks.

This differs substantively from C8/C9's locality check at the uncorrected predictor: C12 tests the implicit equation at its proposed acceptance. It also differs from C10/C11's unverified shared or independent response fit. The check is approximate and provides no quality or indefinite-stability guarantee. It costs3–35 joint field evaluations per accepted update; nominal LR fields remain fixed while the numerical fraction and accepted displacement vary.

Full immutable source inspection confirms hook rejection before the callback/snapshot, base-gradient native moments retained once, optimizer/controller/reference/EMA/buffer/stream/global RNG rewind before each field, and fresh reference/EMA updated only after installing accepted parameters. The final residual-check evaluation occurs at the accepted point, supplying that point's buffer/RNG continuation. Full public dispatch stays inside the serial-autograd context. No evaluator horizon, future shift signal or quality metric enters its residual check. The same unconditional ParticlePrior/API limits remain.
