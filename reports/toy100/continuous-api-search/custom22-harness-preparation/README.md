# RP5 integration plan for the eight custom hosts

These eight require a shared public component transaction; none is faithfully executable by the current GANTrainer unchanged. Optimizer factories alone omit RP5 precision and secant acceptance. A common extension can retain their objectives without dummy generators, missing conditions or legacy K3P fallback. All routes here remain NOT_RUN. This preparation used source reads only: no Torch import, execution, tests, installation or training.

The audited RP5 package is the 1506445 attempt's immutable `rp5-single/source.zip`, SHA256 `43eaad25848e65605afc08b39ff2b714277e0d792315dcb5f5b6f49a25263df7`. Every member matches its declaration and all package files match the active checkout at inspection. `source-map.json` records hashes, definition locations, full frozen task specs/thresholds and actual RP5 recipe. Native100 report/hash copies are now in the research repository's `reports/toy100/continuous-api-search/native100-harness-preparation`.

## One shared route

Extract the existing package transaction beneath GANTrainer into a component engine, with GANTrainer retaining its current ordinary binding. A host supplies a named registry of trainable modules/parameters, two optimizer-role sets, frozen oracle inputs, D/G loss closures, conditional critic views and explicit auxiliary state/streams. The engine owns RP5, eager Adam, KA2, package noise, accepted counters and checkpointing. Host code supplies objectives/data, never learning-rate decisions or controller thresholds. Use `get_recipe(total_steps=None, continuous_precision="rp5", game_update="secant_resolvent", adam_eager_state=True)` and serial backward/nonfused/nonforeach as declared; preserve fixed360/720 bootstrap and RP5 scales.

Keep the exact existing transaction: evaluate base-field predictor; restore all nonparameter state/RNG before corrector; evaluate the same oracle at predicted parameters; compute the existing joint secant over **all** trainable G-side and D-side parameters; retain base-field Adam/KA2 states; apply accepted parameters; restore critic flags; perform only the accepted KA2 reference update/reseed; update requested EMAs; measure precision once on accepted movement and real-data gradients; advance one accepted clock. The complete transaction, higher-order gradients included, remains inside serial backward. Existing scalar-GAN arithmetic must remain identical before any custom quality run.

Materialize exogenous data, conditions, prior sample indices and random variates once or restore their streams exactly. Recompute parameter-dependent generator outputs and encoder routing in each field; caching predictor fakes or encoded outputs would make the corrector wrong. Preserve host draw order, including AE's deliberate postconstruction RNG reset/consumption. Register every owned model, parameter, buffer, optimizer history, EMA, precision reference, modes/flags, role context and host RNG for rollback/resume; the current fixed G/D/prior checkpoint registry cannot cover these hosts.

## Existing support and the remaining API decisions

The current KA2 paired penalty **already supports conditions and module/submodule views**, including a wrapper that exposes the paired critic as a child. Reuse it so the anchor evaluates the corresponding EMA module. Existing scale-host bare lambdas cannot be passed to this identity-checking paired API; use an nn.Module view with the actual critic child. For slow/fast hosts the view swaps the argument order explicitly; do not accidentally differentiate slow context. The new precision probe must similarly receive the copied precision reference root and apply the same frozen context; a closure permanently bound to live D would erase disagreement.

`ReversiblePrecision.observe` currently only calls D(real). Add a shared conditional/role probe binding that computes gradients with respect to the real **data** tensor, excluding condition labels/scales, while preserving the existing raw-coordinate convention. For equal-sized scale roles, combine squared gradient differences as the mean across their original data elements, and advance precision once. This extension needs a declared aggregation rule before use; calling precision.advance once per role changes RP5's temporal constants. Retain original per-role adversarial loss averaging and KA2 penalty invocation order. KA2 warmup counts applied penalty calls, so two/four role calls per accepted step naturally reach800 calls sooner; do not silently convert that counter to accepted updates or multiply it by predictor stages.

`make_generator_optimizer` accepts one latent_table or direct_particles; `make_optimizers` automatically assigns A2 only for exactly one plain ParticlePrior. Two independent tables need explicit independent A2 history ownership and optimizer group roles under the shared engine. Do not concatenate nonleaf tensors as a shortcut, omit A2, or add separate accepted steps. MoG uses its existing public component behavior (not plain-table A2). Direct particles also need an explicit documented base-rate/controller role; the ordinary trainer does not currently define that mapping. These are reviewed component-policy bindings, not established RP5 qualification evidence.

Preserve actual frozen auxiliary injection: `compare_defaults.candidate` sets particle_l2=0 and maps VICReg to recipe.prior_reg, while baseline.Candidate retains cover_weight1.5 and host reconstruction/residual/hold terms. RP5 prior_reg is0. Do not resurrect raw-host .02/.05 defaults or discard independent cover/hold/reconstruction losses. Preserve every auxiliary expression even when the declared recipe coefficient is zero, and record resolved coefficients. Host noise adapters show where output noise is applied: e.g. all wrapped AE decoder calls versus only GAN fake branches in slot/scale hosts. Reuse these application sites with package-owned sigma/RNG, not old scheduled wrappers.

## Review and qualification sequence

First review the component contract and the two unresolved bindings (conditional multi-role precision aggregation and multiple-table/direct-particle optimizer ownership). Then establish exact scalar-GAN parity with existing RP5 and meaningful small CPU checks for rollback/resume, conditioned reference probes, two-table histories and composite objectives. This preparation did not implement or run those checks. Only then bind simpler two_pole/unused-token, conditional trajectory/residual, multi-scale, AE and two-prior hosts using the same engine. A common registered state schema must cover each before quality training.

Preserve all24 observations at ceil(i*budget/24), original live numerical thresholds and five-pass terminal suffix from observation.sustained/protocol.test_verdict. EMA is diagnostic. Remove `schedule_optimizer`, delayed cosine and host evaluator-budget inputs from learner policy; do not call historical `run_legacy` as the candidate path. Snapshot the engine, host bindings, full package and scoring sources; emit resolved host objectives, parameter/optimizer ownership, RNG/backend/init receipts, all actual rates/noise, controller/KA2 counters and accepted secant traces. An extended package is new integration work requiring its own conformance evidence; ancestor RP5 quality does not supply these eight missing results.
