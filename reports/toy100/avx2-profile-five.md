# Local AVX2 dispatch-profile check

The frozen `.01` network-floor, `κ=1` recipe at source commit `a3be165` was rerun on the five hosts whose observations had changed across the two historical CI machines: `ae_gan_hold`, `img_stripes2`, `img_bars4`, `img_blobs4`, and `img_intensity2`. The only intended change from the existing local full-19 replay was setting `ATEN_CPU_CAPABILITY=avx2`, `ONEDNN_MAX_CPU_ISA=AVX2`, `DNNL_MAX_CPU_ISA=AVX2`, and `MKL_ENABLE_INSTRUCTIONS=AVX2` before PyTorch import. Both runs report PyTorch `2.13.0+cu126`, CPU AVX2, the same config SHA-256 `52f2971a…`, and identical hashes for all 118 declared source files. The pinned subset used the same fixed seed and frozen host budgets.

All **120/120 non-timing checkpoint observations** are identical. Every saved optimizer/noise action, loss, noise receipt, and host verdict matches; all five hosts pass in both runs. This supports treating the AVX2 profile as a numerical no-op on this local AVX2 machine. It does not demonstrate bitwise portability to a different AVX512 host. The subset summary is `INCOMPLETE` by design because it selected five hosts; the baseline full-19 summary is 18/19.

The retained evidence is under `artifacts/toy100-accuracy/avx2-profile-five-a3be165/`: `predeclared.json` records the hosts, config, source hashes, and environment before execution; `command.txt` and `run.log` record invocation; `episode/` holds the pinned receipts and source archive; `baseline/` holds the corresponding five original episodes and receipts; `comparison.json` records every equality check; and `hashes.json` gives SHA-256 digests for all 25 retained files. The source archives and config were copied without editing training code.
