# Forge family leaderboard

A **family** can have several **recipes**. Each score belongs to one exact recipe and source. For example, BCAP's selected recipe uses DualNorm; Confidence LR, Finite critic cap and Positive evidence are separate BCAP research recipes, with their own scores.

Click a count for its gates, measurements and evidence. Required lower tiers must pass before advancing.

Counts describe screening and selection evidence. Scientific superiority or public-default adoption requires report-bound accepted calibration and independently frozen confirmation evidence. Software repairs grant neither; unmeasured confirmation remains unmeasured. Tuning effort and task holdout disclosures accompany the full-suite comparison below.

It counts toward qualification again once its re-entry rule is met. A test **removed from the count** stays in its views as a diagnostic, because another counted test already carries its question or it cannot run as declared. Rows come from the notes stored in the view declarations; each details link opens that test's explanation.

DCGAN on deterministic mock RGB data measures finite-update speed and memory. These separate performance-source receipts confer no image-quality, scientific qualification or default-promotion credit. Standard BatchNorm is retained in generator and critic; critic input gradients therefore include batch coupling. Synchronized wall time for one public trainer update, including its critic/generator/prior work; warmup, construction, mock-data generation, evaluation, GIFs and checkpoint writes are excluded.

Every cell is one run; timings are never pooled across devices or contention states. Compare only rows with the same task and matched key (source, runtime/dtype, physical device, initialization and batch streams). Unknown or contended observations are unpaired. Resolution progression changes the task, while each candidate keeps one global recipe. Images/s is B divided by full update time (one D and one G/prior update with separate real batches). Three warmup and ten measured updates give short-window median/p95 measurements; long-horizon policy costs and component phase times remain unknown.

## Reading the results

Counts show passes / required tasks; selected-row pass counts remain unchanged. For rows with run-attempt coverage, the suffix counts genuinely unattempted tasks as not run, constructor refusals as incompatible, missing required artifacts as blocked, and other separate-runtime attempts as diagnostic attempts. A start refusal is not a numerical failure. Rows without that registry retain their recorded missing/preflight counts. No formulation is changed to fit a test. Recorded PASS and FAIL are both executed results. Attempted ERROR, INVALID or INCOMPLETE results show their cause and execution evidence on the family page and earn no pass credit. Zero recorded passes always displays as 0, including unrun families.

Counts retain each original recipe, prior, initialization, budget, serving law and source. Family pages retain exact metrics, phase checks, failures, blockers, historical comparisons and calibration requirements. Observation checks and catalog attempt counts add no benchmark passes; untiered historical studies remain on those detail pages.

## Refresh

```sh
python ops/refresh_forge_readouts.py --check
python ops/refresh_forge_readouts.py
python ops/refresh_forge_readouts.py --reports-only
python reports/forge/regenerate_technique_inventory.py
```

`ops/refresh_forge_readouts.py` checks or refreshes all out-of-date Forge stages end to end when no code changes are needed (auto-selecting an uncontended GPU for the 48-cell DCGAN scaling table via `--scaling-gpu auto`, draining diagnostic attempt coverage and current-source selected-family readouts, and sealing clean-checkout-safe compiled reports; `--reports-only` skips GPU launches).

`python reports/forge/regenerate_technique_inventory.py` regenerates the leaderboard, family pages and experiments-by-tier report from committed evidence and declarations. Register newly measured evidence with `--source-commit <executed-commit>`; advancing the recorded view policy also requires `--advance-policy`.

After any view revision (for example a held or removed test), always add `--refresh-publication`. It rebuilds the counts and pages from the declared views and keeps every recorded verdict and the recorded qualification. Without the flag, the command switches to that mode only when discriminator_stability itself changed; any other view change would take the ordinary publishing path, which re-reads earlier sources from Git.
