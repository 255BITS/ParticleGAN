# BCAP optimizer, loss and retention search

The user authorized **72 BCAP-on global configurations**, using both A6000
GPUs, on 2026-10-08. Each candidate must pass **6/6 Tier 1** before all runnable
**21 Tier 2** requirements execute. The target is at least **10/21 Tier 2**;
selection maximizes required PASS counts by ascending tier, then uses the
configuration content hash to break ties. This target does not relax any gate.
Tier 2 is tuning evidence. Tier 3, independent confirmation and public-default
adoption are outside this study.

## Evidence and hypothesis

Read [experiment memory](../EXPERIMENT_MEMORY.md), the
[options inventory](../bcap-search-options/README.md), the
[smoothing study](../bcap-six/README.md), the
[Tier 2 results](../bcap-tier2/README.md) and the
[convolution results](../bcap-convolution/README.md) before declaring this round.
The historical selected recipe acquires all six smoke targets, then fails
Gaussian stationary/shift retention and word inverse-map retention. It scores
6/21 Tier 2 with four original image setup errors. The separately sourced
convolution implementation trains all four images but fails sustained gates;
stripes loses an acquired target, and intensity reaches it too late. These
archived outcomes motivate this study and retain their original identities.

Hypothesis: reducing late player motion with positive rate floors or stronger
smoothing, adjusting the positive BCAP cap/strength/cadence, or changing the
public optimizer/loss can improve retention without sacrificing acquisition.
No single factor's causality is claimed from compound recipe comparisons.

Predictions and falsifiers, evaluated after the complete search:

- At least one whole configuration passes all six Tier 1 requirements and at
  least ten Tier 2 requirements. No such configuration falsifies the stated
  search success criterion within this finite domain.
- At least one retention variant improves Tier 2 PASS count over the newly
  measured constant-rate convolution-enabled relativistic control. A missing
  control qualification or absent improvement leaves this prediction unsupported.
- Rate decay or stronger smoothing can retain Gaussian quality or the word
  inverse map. These are separate task gates; improved endpoints do not count.
- All candidates keep `reg_arm=b_cap`, `reg_coeff>0`, `reg_kappa>0`, disabled
  K3P/KA2 interventions, no additive training noise and live clean scoring.
  Recipe/stream/source disagreement invalidates attribution; it never fills a
  gate from another candidate.

## Frozen finite domain

[The search definition](../../../configs/forge/search-spaces/bcap-tier2-search-v1.json)
is generated by [prepare.py](prepare.py). It enumerates 36 recipe points at
each of two lazy BCAP cadences (`reg_every=1,4`), giving 72 unique complete
configurations. Lazy cadence four uses the public coefficient-times-interval
rule; it is still BCAP-on. Every structural category is sampled because the
sample count equals the finite population, with protocol-seed-0 sampler state
and draw indices retained in [compiled.json](compiled.json).

| Structural category | Recipe points | Configurations |
| --- | ---: | ---: |
| Convolution-enabled smoothed DualNorm + relativistic | 12 | 24 |
| Same DualNorm + non-saturating, hinge, Wasserstein, least squares | 2 each | 16 |
| Native Adam + all five losses | 2 each | 20 |
| SGDA, global/tensor NSGDA, adaptive NSGDA, DualNorm D-only, prior row-only | 1 each | 12 |

This covers all eight supported BCAP optimizer families and all five losses,
with explicit coverage of 16 structural categories. It does not cover every
one of the 40 optimizer/loss combinations or every numerical field. The
complete flat public field inventory remains in the options report.

DualNorm numerical choices include smoothing `1e-5,1e-3,1e-2`, base step
`.008,.012,.016`, D/prior multipliers, BCAP strengths `1,4`, caps `.5,1`, and
matched prior/network cosine floors `.1,.2,.3,1`. Annealing begins at horizon
fraction `0,.25,.6`; `.6` is inactive for constant-floor controls. Each point
is an explicitly grouped assignment, rather than a Cartesian cross product.
Adam points use steps `.00425,.006`, positive beta2 `.999,.9`, and declared
role rates. Other optimizer rates have their own units. The D-only hybrid
retains its registered network momentum `.5` and Adam rate `.00425`; the
row-only hybrid retains Adam rate `.00425`. Epsilon and inactive SGDA moments
are held fixed. Exact assignments and inherited recipe values are in the plan
and generated configuration cards.

Full DualNorm enables public per-offset convolution updates on every task;
four new structural bases bind its alternative public losses. Joint hosts use
the public two-stream G/E objective. D-only has no convolution opt-in: any
unsupported image execution remains in the required denominator. No copied
training loop or unregistered optimizer is introduced.

## Comparison, gates and budgets

Each task's architecture, data law, actual seen batches, prior, initializer,
sampling, update budget, evaluation cadence and gate stay fixed. Use protocol
seed `0`, the public deterministic initializer, and isolated checkpointed
constructor/data/training-noise/evaluation streams. Task-owned identity/zero
fixtures and finite-vocabulary or image particle-cloud exceptions remain their
explicit separate cohorts. A candidate supplies one global complete recipe
across all tasks. Gaussian and word retention restore their own declared
parent checkpoints, never a different candidate's favorable state.

The current revision-8 view retains all **6/21/2 required rows**, plus its
separate optional clock audit. Forge completes all runnable independent peers
in the current tier before a required failure blocks advancement. Failures,
blocked/unsupported cells, timeouts and unmeasured later tiers remain visible.

Each candidate reserves at most **43,020 worker-seconds**: **2,520** for Tier 1
including its clock audit, and **40,500** for Tier 2. The shared finite ceiling
is **3,097,440 worker-seconds (860.4 worker-hours)**. This is the full declared
timeout reservation, not predicted runtime; historical actual costs suggest
several hours of elapsed time for the whole search. The coordinator uses one
worker on GPU 0 and one on GPU 1, plus its automatic CPU slot where tasks
explicitly require it (at most three workers). There is no GPU sharing.

Stop after the frozen population concludes or declared resources exhaust.
No scientific retries, adaptive resampling, parameter additions, seed-only
experiments, gate changes or horizon extensions are authorized. Queue recovery
may attach to existing workers; it cannot create a scientific retry. The
search uses a separate queue on the larger persistent data drive because the
home filesystem has insufficient space for 72 full artifact cohorts.

## Unattended execution and publication

[run.py](run.py) verifies the preparation, admits the entire roster, and calls
the standard Forge coordinator once with publication callbacks disabled.
Automatic grading and gating continue without agent observation. The wrapper
does not rank or interpret intermediate results. After all submissions are
terminal, it evaluates every configuration together and writes compact final
metrics and a completion marker. Exceptions write a failure marker without
automatic retries. Resume uses the same declarations and queue.

Raw stdout, JSONL events, checkpoints, full plans and original receipts stay
locally or in a byte-verified artifact archive. Commit compact final metrics,
provenance, reproduction sources and actual-training GIFs. Rank by numerical
gates, never GIF inspection. Publish to the existing
[single current leaderboard](../technique-inventory.md); retain archived source
cohorts and avoid combining candidates' cells. A Tier 1 survivor can replace
the displayed whole configuration only through a reviewed complete-row pin.

```sh
python -u reports/forge/bcap-tier2-search/prepare.py --queue-root /path/to/queue
python -u reports/forge/bcap-tier2-search/run.py --queue-root /path/to/queue --gpus 0,1
# Optional human inspection; the agent waits for completion without tailing.
tail -F /path/to/queue/events.jsonl
```
