## The scoped law, and why it is the closest analog

The other families take the clean/live tests: the trained generator's own samples, scored with live weights, from the task's declared prior, without added noise. Atlas and E22 cannot be measured that way without changing them. Their recipes own an equal-mass table of latent rows with row controls (birth/death, copying and rebalancing rows), a policy that selects which weights are served, and a learned output noise. These scoped variants change only what has to change, and say so:

- an explicit equal-mass particle-cloud prior (sigma 0) with a stated reason, instead of the task's mixture prior;
- the complete family recipe unchanged (no overrides, no tuning), schedule-free, protocol seed 0;
- the task's architecture, data law, seen batch sequence, capacity, update budget, timeout, evaluation cadence and numerical gates unchanged;
- scoring with the state-selected served weights and the latent policy exactly as GANTrainer serves it, drawn from isolated evaluation streams; every sample-measuring receipt attests its measured draws.

This is the closest runnable analog of the clean/live tests: the same question, gates and budget, measured on what these recipes actually serve. It is a separate diagnostic cohort. It changes no qualification numerator, no other family's row and no archived verdict, and the original live/MoG tests receive no credit. Lower-tier failures did not stop higher-tier attempts in this user-authorized lane. Checkpoint dependents (Gaussian stability and the three 14k natives) continue their own same-law saved state, also after the parent's gate failed (marked below). Ring extension is regraded only from its own passing uninterrupted ring_hold run and stays BLOCKED (prerequisite) after a failed hold.

## Why the two laws can differ

Atlas and E22 learn a set of points (latent rows mapped through the generator) plus one learned output noise level. GANTrainer serves a sample as a point plus that noise; here the learned noise is about 0.029, close to the data's per-mode width of 0.03. The *clean* law removes the noise before scoring, so each mode becomes a tight cluster: positions and masses can be right while the width is far too narrow. The *as-served* law keeps the noise, so the same trained model is scored with the width it actually produces. Recipe, training, gates, budget, data, cadence and seed are identical; only the evaluation draw differs.

The native 100-mode tests show this most clearly. Their 12 clean holdouts (both families, 7k and 14k) have precision 0.994-1.000 but fail the fixed width limits: |cov trace bias| 0.71-0.99 against 0.1, radial KS 0.36-0.89 against 0.04 (Atlas 0.77-0.82, E22 0.36-0.89); 0 of 12 are within both width limits. As served, the same weights give |cov trace bias| 0.009-0.106 and radial KS 0.004-0.092; 10 of 12 are within both width limits. These ranges are computed from the holdout metrics in [records.json](records.json).

Noise cannot help where a test needs a different shape per component (Ring16 and the unequal-mass/unequal-width vectors), and it does not change tests that fail on modes or on holding a learned state.

## Incompatible tests

These nine tests are refused by an ownership boundary before any host setup, for both families and both laws (one refusal fills both rows). Atlas and E22 control an independent table of interchangeable sample rows; each of these tests needs rows bound to something else.

| Tier | Test | Why Atlas/E22 cannot run it faithfully |
| ---: | --- | --- |
| 1 | unused_token_hold | The student is one shared embedding plus per-token slot corrections, and the test checks that an unused token stays unchanged; there is no table of interchangeable sample rows for Atlas/E22 to sample, copy or rebalance, so a faithful binding needs a conditional (routed) row contract that these independent-row recipes do not have. |
| 1 | ae_gan_hold | An autoencoder GAN whose encoder maps data into the Gaussian-mixture latent law that the test scores; Atlas/E22 refuse encoder recipes while their row controls are on, and replacing the mixture with an equal-weight point table would change the law under test, so it needs a routed encoder task. |
| 1 | five_word_joint_smoke | A joint generator/encoder/critic (BiGAN) in which exactly five latent rows each stay bound to one word and must be recovered by the encoder; Atlas/E22 birth/death would copy rows between words, and the encoder, joint critic and five-row minimum population are outside the independent-row recipes. |
| 2 | five_word_joint_hold | Continues the five-word joint BiGAN from its own smoke checkpoint and inherits the same boundary (an encoder plus rows bound to word identities); there is no compatible scoped smoke state to continue. |
| 2 | trajectory | Each latent row is permanently paired with one source trajectory and the critic judges (source, continuation) pairs, so rows are not interchangeable samples; copying or rebalancing rows would break the pairing, which needs a conditional routing contract. |
| 2 | residual_student | A conditional residual head whose output depends on (source arc, row i), with row i tied to context i and a source-conditioned critic; rows are bound to contexts rather than independent equal-weight samples, which needs a conditional routing and protected-context contract. |
| 2 | cover_leftover | Two separately learned point banks plus scale-conditioned residuals, scored on polar contexts with declared host jitter; one independent equal-weight table cannot represent that joint law. |
| 2 | unipolar | The trainable rows are three role vectors (odd, even, origin) mixed with fixed scale weights; every output uses all of them, the critic is told the scale and the fake batch repeats one vector, so copying one role vector onto another would rewrite the residual law. |
| 2 | mid_scale_identity | Like unipolar plus a fourth mid-scale vector that switches on only near scale 0.5; it is a scale-conditioned blend of role vectors with no sampled rows, so it cannot be bound without routed (conditional) semantics. |

## Recommended next experiments

1. Make `adapters.training_state_receipt` device-independent (drop the CUDA index from the named-stream bindings before hashing), so the clean/as-served pairing check needs no saved-state fallback. It is a source-pinned file, so this needs a new frozen source; it changes no verdict.
2. Decide which scoring law the Atlas/E22 cards declare. The as-served law measures what GANTrainer serves; the clean law isolates where the rows sit. Keep both rows until the owners decide, and treat clean-only native failures (high precision with width far too narrow) as a property of the measurement, not of training.
3. Image Bars4 and Blobs4 find 0 modes under both laws and both families at the declared 600 updates, as in the earlier unchanged-policy diagnostic. Use the saved observations and policy-control receipts to see whether the rows ever leave their initialization before changing anything.
4. Per-component shape (Ring16, unequal mass, unequal width) fails under both laws; one scalar output noise cannot supply a different covariance per component. A per-row or per-mode width study would test whether learned per-row width fixes it.
5. Holding and recovering a learned state fails under both laws with identical training: Atlas ring_hold converges and then loses the hold, E22 never acquires the ring window, Gaussian stability and target-shift recovery miss their windows. These are training-dynamics failures; a one-seed, fixed-budget ablation of the late-phase row controls (birth/death and handover) on ring_hold is the cheapest informative next run.
6. The clock audits fail by construction (absolute step stamps in policy diagnostics, KA2's call-800 switch, the critic-guard release count). Passing needs clock-free versions of those controls.
7. The nine incompatible tests need a routed (conditional) row contract before any Atlas/E22 binding is faithful.
