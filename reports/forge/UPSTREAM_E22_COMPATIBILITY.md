## Decision

The inspected E22 positives **cannot legitimately fill a current Forge learned-MoG qualification or calibration-positive cell**. They can be imported as separately pinned historical evidence once their exact receipts are bound. Their particle law, scoring/serving, initialization, RNG and package differ. The current full independent reference remains unknown where unmeasured. No current-develop Forge defect is demonstrated by E22 being unsupported: the incoming fields and public policy do not exist in that develop API. Rebase work is required before claiming future compatibility.

## What actually changed

PR155 `particlegan/recipes.py:22,54,427–519` changes the default from K3P to **KA2**, adds 20 policy fields and replaces `reg_anchor_decay` with `reg_anchor_min_decay`. The latter is a moment-surprise EMA lower bound, not a numerical rename of fixed decay. `get_recipe("e22")` selects DV12/stationarity, AMSGrad, penalty coefficient 3, learned output noise, row evidence, birth/death, anchored release and served averaging, with `total_steps=None`.

`configs/100gaussians/e22-noout.json` is an override set, not a complete native fixture: it contains placeholders `num_particles=12`, `z_dim=4`, `batch_size=128`. The public preset uses 20,000 / 2 / 2,048; `tests/test_e22_recipe.py` explicitly checks that layering. The misleading historical filename does not mean zero noise: output noise starts at .029 and is learned. Do not construct a native replay from the filename or unresolved dimensions alone.

PR155 `particlegan/ka2.py:1–10,72–133,218–266` retains **799 applied pure-A penalty calls, then a blend from call 800**, plus surprise-history windows. `docs/ka2.md` documents that clock. E22 has no LR schedule/horizon; that alone does not establish Forge’s stronger clock-free eligibility. Fixed call-count gates and the critic guard must remain visible to the hidden-clock audit, even when external step-label perturbation does not affect their private counters.

## Bounded requirements for a later rebase

1. **Resolve public API additions together.** Incoming `GANTrainer.__init__` has only latent/penalty generators and `serial_backward`; it lacks Forge’s additional named generator arguments, MoG capability receipts, `max_steps`/`extend_execution` and sample enumeration. Incoming `init.py` lacks Forge’s `parameter_seeds` and additive atomic `initialize_`; incoming top-level exports lack `prior_capabilities` / `prior_mechanisms`. Preserve/reconcile these public contracts rather than choosing an entire side of conflicts or copying training loops into Forge.
2. **Declare policy/host applicability centrally.** E22 requires ordered `UpdatePolicy` hooks around both backwards and updates, explicit roles, learned-noise optimizer ownership, row evidence, stationarity, birth/death and serving state. Scalar GANTrainer wires them; external/behavioral hosts must bind the same public policy, or block before reservation. Independent full E22 rejects conditional/UCD/encoder/dense-soft rows. `e22_routed` requires explicit `RoutedRows`, paired observations and separate guard contexts; it is a distinct adaptation, not an automatic fallback. `UpdatePolicy` with row controls disabled is an explicit ablation. No copied per-host policy logic.
3. **Separate external budgets from schedule-free formulation.** Forge `_context`, behavior bindings and preflight currently set/check `Recipe.total_steps` against task horizons. Incoming E22 requires `total_steps=None`. Keep the externally bounded task limit independently, and preserve own-parent checkpoint identity; never overwrite None with 7k/14k or remove the scheduler’s hard timeout. Update clock audit to understand reviewed public policy state and to expose KA2’s actual delayed mechanisms rather than inspecting old LR fields only.
4. **Extend instrumentation and checkpoint validation.** Current MechanismAudit’s five K3P hooks do not prove E22 lifecycle execution. Add centrally declared observations for KA2 phases, stationarity decisions, row controls/moves, learned-noise updates and serving source. Current state validators assume old trainer fields/streams. Incoming trainer schema4 rejects old schemas1–3; policy state also owns reservoirs, averages, private RNG, controllers and callback state. Preserve atomic rejection, complete state/next-update parity and restart/event-boundary checks, including serial-backward mode; do not convert archived schema3 checkpoints by changing a number.
5. **Freeze new candidates and scoring deliberately.** `configs/forge/ideas/k3p.json` currently uses empty recipe overrides, so a post-merge default would become KA2 while the card still describes K3P. Give future KA2/E22 declarations truthful formulation identities; keep original K3P receipts/snapshots pinned. Resolve public presets before host overrides; merely setting `Recipe.name="e22"` is a label, not preset selection. Source/recipe/policy/RNG/sampler changes must generate new cohort and compatibility keys. Existing profiles and negative receipts remain unchanged.

These are concrete future integration requirements, not reasons to mark present pinned K3P execution defective. Current develop legitimately lacks E22 controls; unknown recipe/extension fields are rejected, and immutable source identities prevent incoming evidence from silently replacing current results. When the incoming API lands in develop, first establish no-training construction/preflight/sampling/checkpoint contracts and preserved legacy semantics; new science still requires a frozen bounded protocol and Phase D acceptance.
