## Integration and strict failure behavior

`api_run.run_case` adds two optional keyword hooks. Omitted hooks keep the
existing builder, update count, scoring cadence, GIF, numerical grade and
error path. `fixture_factory(case, **original_build_options)` constructs the
unchanged public fixture and attaches the observer. `receipt_finalizer(fixture,
copied_receipt)` adds owner evidence before export; the copy prevents it from
rewriting the runner's numerical verdict.

The observer delegates exactly one original step/read when asked. It checks
the actual public trainer and policy identities, G/D/prior optimizer counters,
successful ordered public lifecycle hooks and all requested owners. Each read
checks the complete typed checkpoint, module modes, named streams, global
Python/NumPy/CPU/CUDA RNGs and selected snapshot before/after. Final attestation
performs no new step, sampling or scoring. Missing ownership, changed source,
state/RNG drift or mismatched clocks are errors.

A factory failure retains zero-update ERROR evidence. A finalizer failure
retains completed updates and the numerical fields under
`numerical_before_observer_error`, while the final receipt is ERROR/FAIL.
Export and final imported-source errors remain authoritative. A sidecar's
`pre_export_numerical_status` is explicitly not the final scientific status.
The exit code is `0` only for final COMPLETE/PASS, `1` for COMPLETE/FAIL and
`2` for any non-COMPLETE result. There is no default, ordinary, speed or
historical qualification granted by this additional cohort.
